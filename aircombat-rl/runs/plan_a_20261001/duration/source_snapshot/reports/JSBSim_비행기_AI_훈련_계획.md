# JSBSim 비행기 AI 훈련 계획 — 논문 검토에 따른 수정안

- 작성일: 2026-10-01
- 대상: `inmo-jang/aircombat-rl`의 JSBSim 기반 2D WVR 공중전 시뮬레이션 정책
- 목적: 사람이 강화학습을 공부하는 일정이 아니라, 비행기 AI를 실제로 훈련하고 비교하기 위한 실험 계획
- 검토 자료: 로컬 논문 9편, 추가한 FAA 비행 교범 Chapter 4, 프로젝트 코드
- 실행 상태: Windows/XPU 환경 구성과 속도 비교, 계획 A의 A0~A2 및 DQN 100만 스텝 추가 실험 완료. 실제 결과와 한계는 13·14절에 기록했다. A3 보상 비교는 후속 단계다.

## 1. 결론과 우선순위

기존 계획은 수정하는 편이 좋다. **먼저 기본 환경에서 재현 가능한 성능을 확보하고, 전이 학습·연속 행동·자기 대전은 각각 효과를 확인한 뒤 채택한다.** 논문에서 사용했다는 이유만으로 모두 한 번에 도입하면 어떤 변경이 성능을 만들었는지 판단하기 어렵고, 노트북에서 실험 비용도 커진다.

추천 순서는 다음과 같다.

1. **계획 A: 기본 정책 확립** — 기존 기준 모델 재현, 관측 개선, 동일 조건의 DQN/PPO 비교.
2. A의 결과에 따라 **계획 B: 전이·커리큘럼**, **계획 C: 연속 행동 PPO/SAC** 중 유망한 방향 선택.
3. 고정 상대에 대한 성능이 안정되면 **계획 D: 과거 정책을 활용한 자기 대전** 검토.
4. 저수준 자동조종기 학습은 별도 후속 연구로 둔다.

B·C·D를 모두 수행해야 하는 것은 아니다. 추가 복잡성과 계산량에 비해 공식 평가 성능이 나아지는 방법만 남긴다.

| 기존 구상 | 수정한 구상 | 수정 이유 |
|---|---|---|
| Circular → Evader → Advantaged → Fair를 필수 순서로 진행 | 목표 과제의 처음부터 학습과 사전 학습 후 전이를 직접 비교 | 과제 간 초기 조건·상대 행동 차이 때문에 전이가 항상 유리하지 않음 |
| PPO를 주력 알고리즘으로 확정 | 같은 관측·보상·행동 공간에서 DQN/PPO 비교 | 논문의 타 환경 성과가 이 프로젝트의 우위를 보장하지 않음 |
| 중간 보상을 추가하면 대체로 좋아질 것으로 가정 | 기본 보상과 조건을 지킨 potential-based shaping을 비교 | 보상 설계가 실제 승리 목표와 어긋날 수 있음 |
| 우선 학습 스텝 수를 늘림 | 관측 정보, 물리 시간에 따른 할인율, 종료·시간 제한 처리를 먼저 점검 | 잘못된 학습 문제를 오래 훈련해도 해결되지 않음 |
| 3회 반복으로 최종 결론 | 3회는 후보 선별용, 최종 후보는 자원에 따라 추가 반복 | 평가 에피소드 수와 독립 학습 반복 수는 서로 다른 불확실성을 측정 |
| 후반에 자기 대전을 반드시 추가 | 고정 상대 학습의 한계를 확인한 경우 도입 | 비정상성, 상대 편향, 과거 능력 망각, 추가 구현 비용이 발생 |

## 2. 현재 프로젝트에서 확인한 조건

코드 검토 기준은 `aircombat-rl` 커밋 `4141a2996507e7f0b2e7a8af26815832b5e13d52`이다. 이후 저장소 변경으로 달라질 수 있으므로 실험 시작 시 사용할 버전을 고정한다.

- 기본 구조는 **정책 → 목표 기수 방향·속도 → 기존 자동조종기 → JSBSim**이다. 정책이 직접 모든 조종면을 제어하는 구조와 구분해야 한다.
- 고도는 기본적으로 20,000 ft로 고정된다.
- 정책 결정은 20 Hz, 물리·자동조종 계산은 120 Hz다.
- 원시 관측은 39차원이며, 자신의 상태·상대 상태·교전 관련 정보를 포함한다.
- 기본 행동은 방향 변화 3개와 속도 변화 3개를 조합한 `Discrete(9)`다. 별도로 2차원 연속 행동 모드도 제공한다.
- 0이 아닌 행동은 매 결정 시점의 현재 상태를 기준으로 목표값을 정한다. 0 행동은 이전 목표값을 유지하므로, 이를 단순한 절대 목표값이나 누적 목표 변화로 해석하면 안 된다.
- 제공된 기준 모델은 DQN이며 기본 학습량은 20만 스텝이다. 단순 기준 관측은 거리 기반 값과 자신의 체력만 사용한다.
- 기준 보상은 승리 시 `+1`, 승리가 아닌 종료 시 `-0.2`, 진행 중에는 `0`이다. 무승부·시간 초과 등을 어떻게 집계하는지는 평가 코드와 함께 확인해야 한다.
- **Circular와 Evader를 포함한 네 과제 모두 상대가 무장한 환경이다.** 앞선 설명에서 이를 비무장 표적으로 표현했다면 그 부분은 정정한다.
- **Fair의 실제 초기 배치는 약 10 km 간격의 대칭적인 측면 배치다.** 단순 정면 대결로 가정하지 않는다.
- 제출 인터페이스는 `Policy(weights).act(obs)` 형태다. 관측 순서, 정규화 통계, 행동 인코딩을 함께 보존해야 한다.

### 3.1 PPO와 SAC에 대한 해석

PPO 논문의 clipping은 실제 정책 성능이 매번 단조롭게 향상된다는 보장이 아니다. 또한 PPO는 오래된 경험을 무제한으로 재사용하는 알고리즘이 아니다. 새 rollout을 수집한 뒤 그 자료를 정해진 epoch 동안 갱신에 사용한다.

SAC는 연속 행동 후보로 적합하지만, 원 논문의 구현과 현대 라이브러리의 구현은 완전히 같지 않다. 원 논문에는 별도 value network가 있고, 현대 구현에서는 구조 및 온도 조절 방식이 달라질 수 있다. 따라서 실험 기록에는 정확한 라이브러리 버전과 구현을 적고, 이를 원 논문의 완전 재현이라고 부르지 않는다. 참고: [Stable-Baselines3 SAC 문서](https://stable-baselines3.readthedocs.io/en/master/modules/sac.html).

로컬 SAC PDF에는 별도 부록이 포함되어 있지 않아 [공식 supplementary](https://proceedings.mlr.press/v80/haarnoja18b/haarnoja18b-supp.pdf)도 확인했다. 그 부록의 네트워크 크기·버퍼 크기 등 역시 이 프로젝트의 확정 설정은 아니다.

### 3.2 공중전 논문과 우리 프로젝트의 차이

Chai 논문의 하위 정책은 조종면을 제어하고 상위 정책은 각속도·추력 등을 다룬다. 우리 프로젝트의 목표 방향·속도와 기존 자동조종기 구조에 바로 대입할 수 없다. 논문의 하위 제어기 훈련에는 약 5천만 스텝 규모의 실험이 등장하므로, 이를 노트북 초기 실험의 기본값으로 삼지 않는다. 세대가 바뀌어도 모든 상대에 대한 성능이 단조롭게 좋아지지는 않는다.

Pope 논문의 계층은 완성된 여러 전문가 정책 중 하나를 선택하는 구조다. 현재 프로젝트의 유도 명령과 추종 제어기 사이의 계층과는 다르다. 논문에는 64 CPU·8 V100 규모의 시스템에서도 시뮬레이션 수집이 병목이 되는 사례가 제시된다. 이는 CUDA를 사용해도 전체 훈련 속도가 GPU 성능만으로 결정되지 않음을 보여준다.

2D HHMARL은 JSBSim이 아닌 자체 환경이며, 이종 다중 에이전트와 무장 선택 등 과제 차이가 있다. 3D HHMARL은 JSBSim을 사용하지만 3D 직접 조종 및 다수 하위 정책·지휘 정책을 포함한다. 특히 3D 논문은 curriculum과 league의 독립적인 기여를 분리하는 ablation이 부족하다는 한계를 밝힌다. 두 논문은 커리큘럼 실험을 할 근거이지, 특정 과제 순서의 성공 보증은 아니다.

### 3.3 과거 상대 집합과 통계적 평가

Bansal 논문에서는 최신 상대만 쓰는 방식의 약점과 과거 정책 샘플링의 이점을 보여준다. 다만 최근 일부 이력을 쓰는 것이 유리한 환경과 전체 이력이 유리한 환경이 달랐다. 따라서 상대 선택 범위를 실험 변수로 둔다. 논문의 표에 등장하는 여러 체크포인트를 독립 학습 seed 수로 해석하면 안 된다.

Agarwal 논문의 핵심은 **학습 과정을 다시 실행했을 때의 변동**과 **하나의 모델을 여러 에피소드에서 평가했을 때의 변동**을 구분하는 것이다. 학습 한 번에 평가 천 번을 수행해도 독립 학습 여러 번을 대체하지 못한다. 3회 반복은 빠른 선별에 사용할 수 있지만, 그것만으로 안정적인 우위를 입증했다고 말하지 않는다.

## 4. 모든 훈련 계획에 공통으로 적용할 준비

### 4.1 관측을 먼저 점검

현재 기준 관측은 거리와 자신의 체력만 사용하는 매우 단순한 형태다. 알고리즘을 교체하기 전에 같은 알고리즘을 유지하면서 관측 개선 효과를 확인한다.

후보 정보는 상대 위치·방향, 상대 속도 또는 상대 운동 관계, 양측 체력, 추적 관련 상태, 남은 시간이다. 실제 환경에서 정책에 제공되는 값만 사용하고, 노출되지 않은 내부 상태를 평가 때도 얻을 수 있는 것처럼 가정하지 않는다. 현재 원시 관측에는 `t_remaining`이 있으므로 이를 남은 시간 입력으로 사용할 수 있다.

- 각도는 불연속 경계가 문제가 되지 않도록 표현을 검토한다.
- 거리·속도·체력 등 서로 다른 단위는 정규화한다.
- 학습 중 얻은 정규화 통계를 저장하고 평가에서는 고정한다.
- 관측 순서와 전처리를 모델과 함께 버전 관리한다.
- 39차원 관측이 자동조종기의 내부 목표값·적분기까지 포함한 완전한 Markov 상태라고 단정하지 않는다.

RNN이나 과거 관측 누적은 후속 후보로 남긴다. 현재 제출 인터페이스의 에피소드별 메모리 초기화 방식부터 정해야 하므로 처음부터 복잡한 기억 구조를 넣지 않는다.

### 4.2 할인율은 실제 시간과 함께 선택

정책이 20 Hz로 행동할 때 `gamma=0.99`의 유효 길이 근사 `1 / (1 - gamma)`는 약 100스텝, 즉 5초다. 이는 엄밀한 시간 제한이 아니라 할인 가중치의 길이를 이해하기 위한 근사다.

120초 뒤 보상에 대한 할인 계수는 다음과 같다.

```text
120초 × 20 Hz = 2,400스텝
0.99^2400 ≈ 3.35 × 10^-11
0.999^2400 ≈ 0.0906
```

종료 보상 중심의 긴 에피소드에서 `0.99`를 논문이나 예제에서 그대로 복사하면 먼 미래의 승리 신호가 매우 약해질 수 있다. 더 긴 시간 범위를 보는 할인율을 후보로 비교하되, `0.999`를 무조건 정답으로 확정하지 않는다. 알고리즘 비교에서는 할인율 탐색 조건과 예산도 맞춘다.

### 4.3 종료와 시간 제한의 의미를 정리

현재 코드에서 시간 초과는 `truncated=True`로 표시되지만, 동시에 승리가 아닌 결과와 종료 보상이 부여되는 경로가 있다. 실험 전에 다음 두 경우를 구분해야 한다.

1. 제한 시간 자체가 경기 규칙의 끝인 유한 시간 과제.
2. 계속될 과정을 데이터 수집 편의상 잘라낸 외부 시간 제한.

두 경우는 value bootstrap과 마지막 shaping 처리에 차이가 있다. 공식 채점 규칙은 유지하면서 학습 래퍼가 그 규칙과 일관되도록 설계한다. 참고: [Gymnasium 시간 제한 처리](https://gymnasium.farama.org/tutorials/gymnasium_basics/handling_time_limits/).

### 4.4 중간 보상은 별도 비교 실험으로 도입

Ng 논문의 potential-based reward shaping을 쓴다면 기본 형식은 다음과 같다.

```text
r'(s, a, s') = r(s, a, s') + gamma * Phi(s') - Phi(s)
```

`Phi`는 유리한 교전 상태 등을 나타내는 bounded potential 후보로 설계한다. 이 프로젝트에서 어떤 potential이 학습에 유리한지는 실험으로 확인해야 한다.

- 학습 알고리즘과 shaping에서 같은 `gamma`를 사용한다.
- `reset()` 직후 초기 상태의 `Phi(s0)`를 저장해 첫 전이를 누락하지 않는다. 현재 래퍼의 `_prev=None` 처리에 주의한다.
- 실제 종료 상태에서는 남는 경계항을 제거할 수 있도록 terminal potential을 처리한다.
- 외부 truncation이면 해당 과제의 bootstrap 정의와 맞춘다.
- shaping이 들어간 누적 보상을 성과 지표로 삼지 않고, 공식 결과로 비교한다.

할인된 shaping 합은 `-Phi(s0) + gamma^T * Phi(sT)`로 정리된다. 종료 처리가 틀리면 마지막 항이 정책 선택에 영향을 줄 수 있다. 또한 단순히 시간에 따라 계수 `alpha_t`를 줄여 shaping 항에 곱하면 일반적으로 같은 보존 논리가 유지되지 않는다. Bansal 논문의 보상 annealing과 Ng 논문의 정책 보존 조건을 혼동하지 않는다.

### 4.5 노트북에서는 병목부터 측정

앞선 장치 확인 기준으로 노트북은 Intel Core Ultra X7 358H, 약 32 GB RAM, Intel Arc B390 내장 GPU 구성이다. NVIDIA CUDA를 로컬에서 사용하는 구성은 아니다. Intel XPU 경로는 후보가 될 수 있지만, 저장소의 CPU/CUDA 경로를 그대로 선택하는 것만으로 지원되는 것은 아니다.

1. CPU로 환경 실행, 짧은 학습, 평가, 저장·재로딩이 되는지 확인한다.
2. 환경 스텝 수집 시간, 신경망 갱신 시간, 평가 시간을 분리해 측정한다.
3. XPU는 해당 PyTorch·드라이버 조합 지원과 사용 연산의 호환성을 검증한 뒤 별도 비교한다.
4. 외부 CUDA 환경에서는 모델 갱신을 GPU로 옮기고, CPU 환경 수집 병렬도를 측정에 따라 조절한다.

기존 Anaconda 환경에서는 PyTorch import 중 OpenMP 런타임 중복 문제가 관찰된 바 있다. 이후 저장소의 별도 `.venv`에 Python 3.12.13·PyTorch 2.14.1 XPU 환경을 만들었으며, GPU 인식·가중치 갱신·CPU/GPU 모델 재로딩을 확인했다. 기존 Anaconda 기본 환경을 변경한 것은 아니다.

실측 결과 Circular 기본 DQN의 1만 스텝 중앙값은 CPU 기본 14.77초, CPU 1스레드 9.84초, XPU 27.88초였다. 그래서 현재 계획 A는 CPU 1스레드로 실행했다. 이 수치는 해당 작은 모델의 배터리 구동 상태 측정값이며 다른 모델로 일반화하지 않는다.

**CUDA/XPU가 JSBSim 물리 계산 전체를 자동으로 GPU로 옮겨 주는 것은 아니다.** 작은 정책망에서는 CPU 수집이나 데이터 이동 비용이 더 크게 작용할 수 있다. 처리량 측정 전에는 몇 시간 만에 학습이 끝난다고 약속하지 않는다.

## 5. 계획 A — 기본 정책 확립: 가장 먼저 실행

### 목표

공식 과제와 제출 인터페이스에서 안정적으로 평가할 수 있는 정책을 만든다. 이후 확장 방법의 효과를 판단할 기준 모델을 확보한다.

### 실험 순서

| 단계 | 실험 | 고정하거나 비교할 조건 | 판단 기준 |
|---|---|---|---|
| A0 | 저장소 기준 모델 재현 | 기존 DQN·관측·행동·보상 | 환경 실행, 저장·재로딩, 평가 경로 정상 동작 |
| A1 | 관측 개선 | DQN과 행동·보상 유지, 관측만 변경 | 공식 성과 개선 및 반복 간 변동 |
| A2 | DQN vs PPO | 같은 관측·보상·상대·`Discrete(9)`·상호작용 예산 | 알고리즘 자체의 차이 |
| A3 | 보상 비교 | 선택한 알고리즘 고정, 기본 보상 vs 고정 potential shaping | 공식 성과, 보상 악용 징후, 안정성 |
| A4 | 최종 후보 확인 | 고정된 검증·시험 절차 | 여러 독립 학습 실행에서 재현되는지 |

Circular는 실행 경로와 기본 행동을 확인하기 위한 첫 실험으로 쓸 수 있다. 그러나 Circular에서 잘됐다는 이유만으로 Fair에서도 전이 학습이 유리하다고 결론 내리지 않는다. 목표가 Fair라면 **Fair를 처음부터 학습한 기준 정책**을 반드시 남긴다.

### 채택·중단 기준

- 제안 모델이 기존 기준 모델보다 실제 평가에서 개선되는지 확인한다.
- 개선이 보상 함수의 점수에만 나타나면 채택하지 않는다.
- 우위가 불확실하면 더 단순한 모델을 유지하거나 사전에 정한 범위에서 추가 반복한다.
- 환경·평가·저장 경로에 문제가 있으면 알고리즘 확장 전에 그 문제부터 해결한다.

## 6. 계획 B — 전이 학습·커리큘럼

### 적용할 상황

계획 A에서 목표 과제를 처음부터 학습하기 어렵거나, 더 쉬운 조건의 학습 결과를 재사용할 가능성이 보일 때 수행한다.

### 핵심 비교

예를 들어 Advantaged → Fair 전이를 시험한다면 다음을 비교한다.

| 실험군 | 훈련 방식 | 확인할 질문 |
|---|---|---|
| B0 | Fair를 처음부터 학습 | 전이 없이 가능한 성능은 어느 정도인가? |
| B1 | Advantaged 사전 학습 후 Fair로 전이 | 같은 총비용에서 성능 또는 학습 속도가 나아지는가? |
| B2, 선택 사항 | Fair 훈련 중 이전 조건 일부를 혼합 | 이전 능력의 망각을 줄이면서 목표 성능을 유지하는가? |

사전 학습 스텝도 총 상호작용 예산에 포함한다. 예를 들어 B1이 사전 학습 30만 + 목표 학습 70만 스텝이면, B0의 목표 학습 100만 스텝과 비교하는 방식이 필요하다. 사전 학습 비용을 제외한 곡선은 전이 이후 속도만 보여주는 보조 자료로 명시한다.

### 구현 조건과 주의점

- 관측 차원뿐 아니라 순서·의미·정규화·행동 인코딩이 같아야 한다.
- 서로 다른 초기 조건 분포로 인해 전이가 오히려 방해할 수 있다.
- Circular → Evader → Advantaged → Fair 전체 사슬을 기본 전제로 두지 않는다.
- 논문에 없는 고정 승률 기준을 보편적인 승급 규칙으로 제시하지 않는다. 단계 전환 기준은 실험 전에 정한 자체 기준으로 기록한다.
- 전이 이득이 불명확하면 과제별 독립 정책을 유지한다.

## 7. 계획 C — 연속 행동 PPO/SAC

### 적용할 상황

기본 정책이 의미 있는 행동을 학습했지만 9개 이산 행동의 해상도가 성능을 제한하는지 확인하고 싶을 때 수행한다.

### 핵심 비교

1. **이산 PPO vs 연속 PPO**: 알고리즘을 유지하며 행동 표현의 효과를 본다.
2. **연속 PPO vs SAC**: 같은 연속 행동 조건에서 알고리즘의 효과를 본다.

처음부터 이산 DQN과 연속 SAC만 비교하면 행동 공간과 알고리즘이 함께 바뀌므로 무엇이 개선을 만들었는지 구분하기 어렵다.

### 실험 조건

- 우선 고정된 상대를 사용한다.
- 관측·정규화·보상·할인율 후보·시작 조건·평가 규칙을 맞춘다.
- 행동 범위와 실제 방향·속도 목표값으로의 변환을 확인한다.
- DQN 가중치를 SAC에 그대로 옮길 수 있다고 가정하지 않는다.
- 환경 상호작용 수와 실제 소요 시간 둘 다 비교한다.
- SAC의 replay buffer 크기, 보상 스케일, 엔트로피 설정은 기록하고 제한된 범위에서 조정한다.

SAC의 replay가 과거 경험을 재사용한다는 장점은 있지만, 상대가 계속 바뀌는 자기 대전에서는 과거 경험의 분포가 현재 상대와 달라질 수 있다. 이는 우리 구현에서 검증할 설계 우려이며, 원래 SAC 논문이 이 공중전 문제에서 실패를 입증했다는 뜻은 아니다.

## 8. 계획 D — 과거 정책 집합을 활용한 자기 대전

### 적용할 상황

고정 상대에 대해서는 성능이 안정적이지만 특정 행동 패턴에 과적합하거나, 다른 정책과 대전할 때 취약한 경우 수행한다.

### 초기 구조

- 학습자는 하나만 둔다.
- 상대는 규칙 기반 기준 상대와 일정 간격으로 저장한 과거 정책으로 구성한다.
- 에피소드가 시작되면 상대 정책을 고르고, 해당 에피소드 동안 고정한다.
- 양쪽 시작 위치 또는 역할에서 평가한다.
- 과거 정책 전체와 최근 일부를 사용하는 방식은 각각 비교 후보로 둔다.

처음부터 여러 학습자가 동시에 갱신되는 대규모 league를 구축하지 않는다. 우선 단일 학습자와 고정된 상대 집합으로 비용과 효과를 확인한다.

### 반드시 필요한 비교

**동일한 추가 학습 예산으로 고정 상대 학습을 계속한 정책**을 대조군으로 둔다. 자기 대전 정책의 성능이 높아져도 단순히 더 오래 학습한 효과일 수 있기 때문이다.

| 평가 항목 | 확인 내용 |
|---|---|
| 규칙 기반 상대 | 기존 능력을 유지하는가? |
| 여러 과거 정책 | 최신 상대 하나에만 맞춘 대응인가? |
| 훈련에 쓰지 않은 상대·초기 조건 | 새로운 조건에서도 성능이 유지되는가? |
| 양쪽 역할 | 특정 시작 위치나 역할에 편향되어 있는가? |
| 상대별 결과 행렬 | 평균 향상 뒤에 특정 상대에 대한 큰 퇴보가 숨었는가? |

새 모델이 직전 모델을 한 번 이겼다는 이유만으로 자동 교체하지 않는다. 검증 결과와 상대별 성능을 함께 본다.

### 프로젝트에 추가로 필요한 구현

저장소에는 과거 정책을 상대 드라이버로 연결할 수 있는 `PolicyDriver`가 있지만, 완성된 상대 풀 관리·선정·훈련 루프가 제공되는 것은 아니다. 또한 행동 해석이 환경의 `decode`에 연결되어 있으므로, 처음에는 학습자와 과거 상대의 행동 공간을 같게 유지한다.

관련 코드: [상대 드라이버와 기준 상대](https://github.com/inmo-jang/aircombat-rl/blob/4141a2996507e7f0b2e7a8af26815832b5e13d52/aircombat_gym/wvr/baselines.py).

## 9. 실험 예산과 평가 방식

아래 수치는 **실행을 시작하기 위한 자체 예산 제안**이며, 논문이 이 프로젝트의 수렴에 충분하다고 입증한 수치가 아니다. 노트북 처리량을 측정한 뒤 현실적인 범위로 조정한다.

| 단계 | 제안 예산 | 목적 |
|---|---|---|
| 동작 확인 | 짧은 rollout·학습·평가·저장 재검증 | 실행 경로와 인터페이스 확인 |
| 후보 선별 | 설정당 독립 학습 3회, 각 20만~50만 스텝 | 학습 신호와 큰 차이 확인 |
| 유망 후보 확장 | 최대 2개 설정, 설정당 실행을 약 100만 스텝 추가 확장하는 예산을 우선 검토 | 더 긴 훈련에서 순위와 안정성 확인 |
| 최종 확인 | 자원이 허용하면 5~10회의 독립 학습 실행 | 학습 변동을 포함한 불확실성 평가 |

초기 선별 예산에서 학습 신호가 없다는 이유만으로 알고리즘이 원천적으로 부적합하다고 단정하지 않는다. 반대로 무제한으로 예산을 늘리지도 않는다. 원인 점검 후 확장 여부와 상한을 정한다.

### 평가 원칙

1. **학습 seed**, **검증 에피소드 seed**, **최종 시험 에피소드 seed**를 구분한다.
2. 모델과 설정의 선택은 검증 집합에서 한다. 최종 시험 집합은 선택 과정에 반복 사용하지 않는다.
3. 공식 평가의 주 지표를 유지한다. 별도로 승리·사망·상호 격추·시간 초과, 잔여 체력, 유효 추적·무장 조건 유지 등 진단 지표를 기록한다.
4. Fair 등 대칭 평가에서는 양쪽 역할을 포함한다.
5. 학습 실행 단위의 결과와 변동을 보고한다. 에피소드만 재표집해 학습 간 변동을 무시하지 않는다.
6. 두 방법의 차이와 그 불확실성을 보고한다. 한 방법의 최고 seed와 다른 방법의 평균을 비교하지 않는다.
7. 사전 학습과 후보 선택에 사용한 계산량도 별도로 기록한다.
8. 표본이 적어 결론이 불명확하면 **우위 미확인**으로 남긴다. 5~10회 반복도 자동으로 통계적 확실성을 보장하지 않는다.

저장소의 공개 검증·개발용 평가와 실제 숨겨진 채점 조건이 같다고 가정하지 않는다. 공개 조건에 대한 세밀한 튜닝이 일반화를 대체하지 못한다.

## 10. 자동조종기를 더 발전시키는 방향

가능성은 있지만, 정책 학습과 분리해서 검토하는 편이 좋다. 현재 자동조종기는 이미 여러 제어 루프, 제한 처리, anti-windup 등을 포함한다. 다른 논문에서 RL 제어기가 PID와 비교해 좋았다는 결과만으로 현재 제어기를 교체해야 한다고 판단할 수 없다.

또한 학습 환경의 자동조종기를 변경해도, 표준 평가기가 기존 자동조종기를 사용하면 변경한 제어기가 제출 정책과 함께 전달되지 않는다. 먼저 수정된 제어기를 평가 환경에서도 사용할 수 있는지 확인해야 한다.

후속 실험을 한다면 다음 순서로 분리한다.

1. 기존 자동조종기의 방향·속도 명령 추종 오차, 오버슈트, 정착 시간 등을 측정한다.
2. 교전 정책의 한계인지 제어기의 명령 추종 한계인지 구분한다.
3. 동일한 조건에서 제어기 개선을 평가한다.
4. 제어기를 바꿨다면 상위 정책을 재학습하거나 적응시키고, 그 비용까지 포함해 비교한다.

논문은 새로운 제어기 연구의 가능성을 보여주지만, 현재 과제에서 저수준 제어기 교체가 가장 효율적인 첫 단계라는 근거는 부족하다.

## 11. 실행 시 의사결정

```text
환경·저장·평가 경로 확인
        ↓
계획 A: 기준 모델 → 관측 개선 → DQN/PPO → 보상 비교
        ↓
목표 과제에서 재현 가능한 성능 확인
        ├─ 사전 학습 이득을 검증하려면 → 계획 B
        ├─ 행동 해상도의 한계를 검증하려면 → 계획 C
        └─ 상대 다양성·과적합 문제를 다루려면 → 계획 D
        ↓
같은 예산의 대조군과 비교
        ↓
검증으로 최종 후보 선택 → 독립 시험 → 제출 정책 저장
```

첫 실행은 계획 A다. 이후 B·C·D는 각각의 질문에 답하기 위한 선택 실험으로 운영한다. 공식 성과와 재현성으로 효과가 확인된 변경만 최종 정책에 반영한다.

## 13. 계획 A의 1차 실행 결과 — 2026-10-01

**A0 원본 재현과 A1·A2의 통제된 비교를 완료했다.** 안정적인 정책 확립 전체가 끝났다는 뜻은 아니다.

원본 DQN은 기존 학습 루프 그대로 seed 0에서 20만 스텝을 학습했고, 검증 0/30·별도 시험 0/40이었다.
그 뒤 공통 설정을 정리해 기본 관측 DQN, 개선 관측 DQN, 개선 관측 PPO를 각각 204,800스텝씩 seed 0·1·2로 훈련했다.
공통 할인율은 0.999, 보상은 기존 종료 보상이며, 실제 경기 시간 종료에서 bootstrap을 끊도록 학습 래퍼만 조정했다.
물리·상대·행동·공식 평가 규칙은 유지했다. 31개 개선 관측에는 상대 위치·속도, 양측 운동 상태·체력·추적 상태, 남은 시간 등을 포함했다.

| 비교 조건 | seed 0 시험 | seed 1 시험 | seed 2 시험 | 3회 평균 승률 |
|---|---:|---:|---:|---:|
| 기본 관측 DQN | 0/40 | 0/40 | 0/40 | 0% |
| 개선 관측 DQN | 0/40 | 0/40 | 7/40 | 5.83% |
| 개선 관측 PPO | 0/40 | 0/40 | 0/40 | 0% |

선택 모델은 **개선 관측 DQN의 seed 2, 204,800스텝 체크포인트**다. 검증 6/20으로 시험 전에 선택했고,
다른 시험 조건에서 **7/40 = 17.5%**를 기록했다. 좌석별로 red 5/20, blue 2/20이며,
전체 결과는 승리 7·사망 25·상호 종료 3·시간 초과 5다.

17.5%는 가장 잘 나온 선택 모델 하나의 성적이다. 개선 관측 DQN 조건 전체 평균은 5.83%이며,
다른 두 독립 학습에서 성과가 재현되지 않았다. 따라서 이 모델은 다음 개선의 기준 후보로 사용하고,
안정적인 정책이나 DQN의 일반적 우월성을 확보했다고 해석하지 않는다.

본 비교의 학습 중 완료된 1,292개 에피소드에서는 승리 보상이 한 번도 발생하지 않았다.
탐험을 끈 평가에서 일부 승리가 나왔지만, 종료 보상만으로 학습 신호가 충분한지는 여전히 문제다.
후속 후보는 **관측·알고리즘을 고정하고 중간 보상의 효과를 확인하는 A3**다.
기존 종료 보상과 조건을 지킨 potential shaping을 같은 예산·seed에서 비교하고,
이미 확인한 이번 시험 집합은 후속 모델 선택에 쓰지 않는다. A3 추가 학습은 아직 실행하지 않았다.

### 학습량 확대를 먼저 확인 — 2026-10-01 추가 요청

사용자 요청에 따라 A3보다 먼저 개선 관측 DQN을 **204,800 → 512,000 → 1,024,000스텝**으로 비교한다.
기존 seed 2의 검증 승리는 마지막 시점에서 처음 나타났으므로 학습 종료가 빨랐을 가능성을 확인한다.
seed 0·1·2, 관측·보상·할인율·네트워크·최적화 설정을 고정하며,
탐험 확률 감소도 기존의 절대 기간인 첫 20,480스텝으로 유지한다.
기존 실행에 replay buffer가 없어 새로 시작하고, 같은 실행 경로의 세 시점을 비교한다.
각 예산 내 검증 최선 모델과 해당 예산의 마지막 모델을 모두 새 시험 band 1200000에서 평가한다.
시험 전에 모든 선택을 고정하고, 3개 시드의 평균과 편차를 함께 보고한다.
실행에는 앞서 더 빨랐던 CPU 설정을 사용하고, 이번에는 재생 버퍼도 저장한다.

## 14. 추가 학습 결과 — 100만 스텝 비교 완료

개선 관측 DQN을 seed 0·1·2에서 각각 **1,024,000스텝**까지 훈련했다.
총 3,072,000스텝이며, CPU 프로세스 3개로 학습·검증·별도 시험까지 약 24.7분 걸렸다.
초기 204,800스텝에서는 기존 실행과 세 모델의 가중치·검증 결과가 모두 정확히 일치했다.

각 예산 이내에서 검증으로 고른 모델을 **같은 새 시험 조건**으로 비교했다.
다음은 각 모델당 40경기, 좌석별 20경기 결과다.

| 예산 | seed 0 | seed 1 | seed 2 | 3회 평균 승률 |
|---|---:|---:|---:|---:|
| 204,800 | 0/40 | 0/40 | 10/40 | 8.33% |
| 512,000 | 0/40 | 0/40 | 10/40 | 8.33% |
| 1,024,000 | 10/40 | 6/40 | 10/40 | **21.67%** |

100만 스텝 예산에서 실제 선택된 시점은 seed 0: **819,200**, seed 1: **972,800**,
seed 2: **204,800**이었다. 다른 두 시드도 뒤늦게 성과를 얻어 평균이 13.33%p 올랐다.
세 시드 간 표본 표준편차는 14.43%p에서 5.77%p로 줄었지만, 반복 3회만으로 안정성을 확정할 수는 없다.

**50만·100만 스텝의 마지막 모델들은 세 시드 모두 시험 0승/40경기였다.**
추가 학습으로 좋은 중간 정책을 얻었으나 이를 유지하지 못했다.
검증 후보 수도 함께 늘었으므로, 위 개선은 추가 학습과 중간 체크포인트 선택을 함께 적용한 결과다.
이후에도 마지막 가중치를 무조건 채택하지 않고 검증 최선 모델을 보존한다.

대표 모델은 검증 6/20이었던 기존 seed 2의 204,800스텝 모델로 유지했다.
이번 새 시험에서 10/40이었지만 이전 시험의 7/40과는 초기 조건이 다르므로,
같은 모델의 승률 차이를 추가 학습의 효과로 해석하지 않는다.
학습 중에는 총 2,078경기 중 8승만 발생해 긍정적인 보상이 여전히 드물었다.

다음 우선순위는 **더 긴 학습만 반복하기보다 A3 보상 비교로 성능 유지와 학습 효율을 확인**하는 것이다.
동일한 개선 관측 DQN·3개 시드·100만 스텝 예산에서 종료 보상과 고정 potential shaping을 비교한다.
탐험 일정은 그대로 두고, 탐험 변경은 별도 실험으로 분리한다.
이번 시험 band 1200000은 다시 미사용 시험으로 취급하지 않는다. A3 학습은 아직 실행하지 않았다.
