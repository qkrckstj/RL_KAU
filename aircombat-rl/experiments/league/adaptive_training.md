# 관측에 따른 추격 전환 학습

2026-10-06 15:34 KST에 `runs/league_adaptive_20261006`에서 시작했다.
실제 진행 상태는 프로세스와 이 폴더의 `progress.json`, `completion.json`, `failure.json`으로 확인한다.
기존 최종 정책 `refine_2200`과 첫 리그 묶음의 결과는 그대로 보존한다.

## 학습 내용과 근거

확인된 수동 추격 설정은 새 개발 조건의 Evader 80경기에서 10승, 기존 정책은 0승이었다.
이를 모든 상황에 적용해도 좋은지는 확인되지 않았다. 두 정책을 고정하고,
초기 0.5~6초 동안 관측한 상대 선회·속도 변화·기수 변화·접근 속도로 사용할 정책을 선택한다.
선택 후에는 해당 정책이 매 시점의 공개 관측에 반응한다. 상대 이름·정책 종류·미래 행동을 입력하지 않는다.

학습 변수는 관측 시간과 선형 분류 계수, 총 6개다. CEM 탐색이며 신경망 학습이 아니다.
새 학습은 기존 부모·과거 후보·DDQN·봇·수동 추격 설정을 중복 제거한 19종을 상대한다.
과거 시험에만 썼던 Lead/Circler/DDQN seed0도 이제 관측한 상대다.

## 자동 실행 순서

1. 기존 소스·물리·정책의 해시를 확인하고 새 계획·소스 사본을 동결한다.
2. 기존 정책만 고르는 조합을 실제 양 좌석 비행으로 검사한다. 이 검사는 통과했다.
3. 난수 2300/2301/2302로 각 3세대, 세대당 10후보를 탐색한다. 최대 3개 CPU 작업자를 쓴다.
4. 각 후보는 상대당 양 좌석 포함 4경기로 선별하고, 상위 후보와 보존 부모를 새 훈련 조건 8경기로 재비교한다.
5. 별도 개발 조건 20경기/상대에서 저장할 체크포인트를 고른다. 기존 정책을 항상 선택할 수 있다.
6. 세 탐색 결과와 부모를 새로운 개발 조건 40경기/상대에서 비교한다.
7. Evader 개선 및 전체 상대 성능 유지 조건을 통과한 후보만 선발한다. 선발 결과를 동결한 뒤 최종 시험을 연다.
8. 최종 시험은 정책당 40초기조건×양 좌석×19상대=1,520경기다. 부모와 세 탐색 결과를 모두 보고한다.

선발 조건은 Evader 승률 +5%p 이상, 전체 승률 하락 0.5%p 이내, 목적함수 상승,
하위 1/4 상대 점수 하락 2%p 이내, 어느 상대든 승률 하락 15%p 이내, Evader 패배 증가 없음이다.
최종 통과에는 선택 정책의 전체 승률 차이와 Evader 승률 차이의 초기조건 단위 95% 구간 하한이 모두 양수여야 한다.
최종 시험 후 더 잘 나온 다른 후보로 선택을 바꾸지 않는다. 전체 승률과 상대별 승/무/패를 함께 보고한다.

## 재개와 산출물

`aircombat-rl` 폴더에서 의존성이 설치된 Python으로 실행한다.
실제 동일 실행이 살아 있다면 재실행하지 않는다. 중단돼 프로세스가 없다면 같은 소스·입력·경로로 재개할 수 있다.
이미 저장된 후보·경기는 설정이 일치할 때만 재사용한다. 소스나 설정을 바꿀 때는 새 실행 폴더가 필요하다.

```powershell
python -m tools.league_adaptive_train --out runs/league_adaptive_20261006
```

`plan.json`은 상대·계수·예산·소스/입력 해시, `source_snapshot/`은 실행 소스다.
`smoke.json`은 실제 비행 일치 검사, `s2300/` 등의 폴더는 후보·경기·분포·난수 상태다.
`frozen_selection.json`은 시험 전 선택, `final_claim.json`은 시험 개봉,
`completion.json`은 통과·실패·개발 개선 없음 중 하나를 기록한다.
실패 후보도 보존하며 다음 상대 목록에 추가할 수 있다. 후속 변경은 새 실험으로 기록한다.

3회 탐색은 같은 학습된 전문가 두 개를 공유한다. 학생들의 실제 정책에 대한 검증이나
모든 연속 상태에 대한 보장을 의미하지 않는다. 첫 실행 시점에는 새 정책의 성능 결과가 아직 없다.
