# 새 조건 평가 결과와 전술 파라미터 학습

## 최신 결과: CEM 완료, 전체 상대 비교 실행

전술 CEM의 두 탐색·개발 평가·16판 기본값 재현 검사가 모두 완료됐다. 실제 대결은 **7,120판**, 탐색별 고유 파라미터 조합은 33개다. 학습 실행 후의 첫 자동 검증이 실수의 완전 일치 검사에서 실패해 프로세스 종료 코드는 1이었다. 합산 순서에 따른 차이는 확인된 프로필에서 최대 약 2.22e-16이었다. 원본 소스·결과를 수정하지 않고 `tools/league_extend_parameter_analysis_v2.py`로 집계 실수값만 절대 오차 1e-12 이내로 비교했다. 정수 경기 수·원시 승패·후보 파라미터·캐시·선택 검사는 그대로 유지했으며 **v2 검증은 종료 코드 0, `raw_parameter_analysis.json` 검증 완료**이다. 1e-8 차이와 경기 수 차이를 거부하는 경계 검사도 통과했다.

| 정책 | 새 99M 개발 승률 | 코드 계열 균등 승률 | 취약 사분위 점수 | 최악 상대 점수 |
|---|---:|---:|---:|---:|
| 기본 extend 제어기 | 67.96875% | 74.9275% | 0.453125 | 0.25 |
| CEM 6800 | 70.703125% | 79.3116% | 0.4453125 | 0.3125 |
| CEM 6801 | 66.796875% | 73.7862% | 0.4765625 | 0.375 |

첫 후보는 평균 승률과 최악 상대 점수가 개선됐지만 취약 사분위 점수는 조금 낮았다. 두 번째는 취약 성능이 개선되고 평균 승률이 낮았다. 따라서 CEM 방식 전체의 일관된 개선이나 배포 승격은 아직 주장하지 않는다. 개발 순위로 6800을 지명하고 6801도 독립 반복 비교에 유지한다. 두 검색 모두 약 1,500m에서 이탈하고 기본값보다 낮은 평상시 속도를 선택했지만, 각 파라미터의 인과 효과를 분리한 실험은 아니다.

현재 실행은 **`runs/league_extend_parameter_assess_20261007`**, 실행기는 `tools/league_extend_parameter_assess.py`이다. 기존 132개 상대와 새 CEM 후보 2개, 새 100M 초기 조건 **8개·양 진영**에서 비교한다. CEM 두 정책·순수 제어기는 결정적 정책으로 한 번씩, 보존한 PPO6700은 행동 난수 두 개로 실행한다. 합계 **10,720판(670개 묶음)**이며 CPU 작업자 8개(NumPy 4·일반 4)를 사용한다. 첫 CEM 후보 대 PPO·기본 제어기의 전이가 주목적이고, 다른 CEM 반복과 직접 대결도 포함한다.

분석기는 `tools/league_policy_assessment_metrics.py`이며 기존 검증된 4,800판에서 종전 통계와 동일함을 확인했다. 결정적 정책을 가짜 독립 반복으로 복제하지 않는다. 초기 조건 재표집은 양 진영과 상대들을 함께 유지하며, PPO 행동 난수 변동을 별도로 반영한다. 기존 132개 묶음과 새 CEM 2개 묶음을 구분해 보고한다. 반응형 8개 상대 진단은 132개 묶음의 부분집합이며, 학습에 이미 소비됐으므로 미사용 상대 시험이 아니다. 이번 단계는 새 조건의 넓은 비교이고 최종·미사용 상대 확인은 별도다.

```powershell
& '.venv-cpu\Scripts\python.exe' -X utf8 -u -m tools.league_extend_parameter_assess --source runs/league_extend_parameter_train_20261007 --out runs/league_extend_parameter_assess_20261007
```

실행 중 중복 시작하거나 동결된 파일을 수정하지 않는다. 완료 시 원시 비교 검증을 자동 실행한다. 긍정적인 넓은 전이가 확인되면 후보를 고정한 뒤 미사용 상대·조건 확인으로 넘어가고, 그렇지 않으면 기존 PPO·제어기를 보존하면서 약점을 후속 학습에 반영한다. GitHub 업로드는 하지 않는다.

## 완료한 전이 평가

`runs/league_extend_transfer_v2_20261007`는 **7,392판, 종료 코드 0**으로 완료됐다. `raw_transfer_analysis.json`에서 원시 승패·양 진영·조건·집계를 검증했다. 학습 모델 두 개는 서로 다른 초기 가중치에서 나온 최종 체크포인트이고, 첫 모델은 앞선 개발 결과로 미리 선택했다. 모델마다 행동 난수 두 개를 평균했다. 아래 세 묶음은 같은 98M 초기 조건 네 개와 양 진영을 사용했다.

| 정책 | 기존 120개 상대 승률 | 같은 상대 코드 계열 균등 승률 | 새 학습 모델 4개 변형 상대 승률 | 미사용 반응형 8개 상대 승률 |
|---|---:|---:|---:|---:|
| PPO 6700 | 86.71875% | 82.9241% | 35.9375% | 53.125% |
| PPO 6701 | 87.34375% | 81.3301% | 40.625% | 48.4375% |
| 미학습 sampled prior6 | 86.71875% | 79.7920% | 32.8125% | 47.65625% |
| 순수 extend 제어기 | 85.520833% | 78.8396% | 18.75% | 51.5625% |

6700의 기존 상대 균등 승률은 시작 정책과 같았다. 코드 계열 균등 승률은 +3.1321%p였고, 고정 상대·네 초기 조건·두 행동 난수에 조건부인 교차 재표집 구간은 +0.8635~+5.5185%p였다. 새로운 반응형 상대에서는 +5.46875%p였으나 같은 구간이 **−9.375~+20.3125%p**로 넓다. 미사용 상대에 대한 확정적 우월성이나 임의의 미래 참가자에 대한 승률로 해석하지 않는다.

미사용 상대 최악 점수(승 1·무 0.5·패 0)는 6700이 0.4375, 6701이 0.1875, 시작 정책이 0.3125, 순수 제어기가 0.375였다. 첫 학습 모델은 유망하지만 두 독립 반복에서 약점 개선이 일관되지는 않았다. 반응형 오른쪽 이탈·감속 추적 상대의 낮은 승률도 남았다. **학습에 의미가 없었다고 결론내리지 않는다.** 두 PPO 후보를 보존하고 이후 새 모델의 상대·비교 대상으로 유지한다. 전역 배포 정책을 승격하지 않았다.

## 현재 실행: CEM으로 전술 파라미터 학습

현재 폴더는 `runs/league_extend_parameter_train_20261007`, 실행기는 `tools/league_extend_parameter_train.py`이다. **PPO 신경망 업데이트가 아니라 CEM 파라미터 탐색**이다. 공식 FairFight 물리·시작 조건·행동·무기·승패 기준을 그대로 사용하며, 공개 39개 관측만 받는다.

7개 파라미터는 이탈 시작 거리, 이탈 지속시간, 재시도 대기시간, 이탈 각도, 평상시 목표 속도, 선행 조준 시간 상한, 먼 거리 추적 시 속도 증가량이다. 기존 제어기를 정확히 재현하는 기본값은 각각 `1300, 8, 8, 20, 600, 3, 0`이다. 기존 CEM·PPO·순수 extend 정책 파일은 수정하지 않았다.

기본값의 동작은 기존 제어기와 12,000개 연속 관측의 행동·내부 상태가 같았다. 두 단위 검사를 통과했고, 본 실행의 초기 **16판 실제 비행 비교에서도 전체 에피소드와 요약이 일치**했다. 이 검증 후 실제 파라미터 탐색이 시작됐다.

- 독립 탐색 난수 6800/6801, 각각 4세대 × 후보 10개, 엘리트 3개를 사용한다.
- 기존·새 학습·반응형 상대 132개를 모두 목록에 보존한다. 실제 탐색은 순수 제어기의 취약 상대 8개와 코드 계열 다양성을 반영한 **24개 상대**로 수행한다. 모든 132개를 매 후보마다 학습시키는 것은 아니다.
- 학습 조건은 290M/291M 각 두 초기 조건·양 진영이다. 첫 탐색과 두 번째 탐색은 난수와 학습 조건이 다르다.
- 각 세대에서 현재 최고 후보와 기본 제어기를 유지한다. 완전히 같은 파라미터와 조건은 기존 결과를 재사용하며 새 경기로 중복 집계하지 않는다. 일반적인 경우 탐색당 고유 조합 33개, 총 학습 대결 6,336판이다.
- 학습 선택 점수는 `0.75 × (상대 균등 승률 + 코드 계열 균등 승률)/2 + 0.25 × 취약 사분위 점수`이다. 동점은 사분위·최악 점수·불리한 상대 수로 구분한다. 이는 학습 후보 선택 기준이고 공식 경기 판정은 그대로다.
- 탐색별 최고 후보를 학습 결과로 먼저 고정하고, 새 99M 조건 네 개·양 진영과 32개 개발 상대에서 두 후보와 기본값을 비교한다. 개발 대결 768판, 실제 비행 동일성 검사 16판을 포함해 예상 합계는 **7,120판**이다. 동일 후보가 더 중복되면 실제 실행 수는 줄어든다.
- CPU 작업자 8개, BLAS/OMP/MKL 스레드 각 1개다. 새 반응형 상대는 이 단계부터 학습에 소비됐으므로 다시 미사용 상대라고 부르지 않는다.

완료 시 `tools/league_extend_parameter_analysis.py`가 원시 경기·프로필·난수에 따른 후보 생성·캐시 재사용·CEM 업데이트·선택·개발 결과를 재계산한다. 비교 후 강한 후보가 있으면 보존한 PPO와 전체 상대 목록에서 다시 확인한다. 지금 단계는 최종 시험 또는 목표 완료가 아니다. GitHub 업로드는 하지 않는다.

```powershell
# aircombat-rl 디렉터리에서, 이미 실행 중이면 중복 실행하지 않는다.
$env:OPENBLAS_NUM_THREADS='1'
$env:OMP_NUM_THREADS='1'
$env:MKL_NUM_THREADS='1'
& '.venv-cpu\Scripts\python.exe' -X utf8 -u -m tools.league_extend_parameter_train --source runs/league_extend_transfer_v2_20261007 --out runs/league_extend_parameter_train_20261007
```

현재 PID와 세션은 `docs/LEAGUE_STATE.json` 및 실행 폴더의 `runtime.json`에서 확인하고 실제 프로세스와 대조한다. 실행 중 덮어쓰는 파일을 반복해서 읽지 말고 완료된 `candidate.json`, `generation_*.json` 또는 프로세스 세션 출력을 확인한다.
