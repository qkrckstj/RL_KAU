# 새 CEM 상대를 포함한 PPO 이어 학습

## 완료 결과와 후속 대결

두 반복 모두 정상 종료했고, 총 **7,864,320 추가 학습 단계**와 **1,792 개발 평가 경기**의 원시 기록 검증을 통과했다. 같은 학습된 조상에서 갈라진 두 연속 학습이며, 처음부터 독립적으로 학습한 두 모델은 아니다.

| 추가 단계 | 6900 승률 | 6901 승률 |
|---|---:|---:|
| 시작 | 61.72% | 61.72% |
| 1,310,720 | 65.23% | 60.55% |

둘 다 사전에 정한 연장 기준을 충족했지만, 마지막 구간에서는 성능이 후퇴했다. 각 2,621,440단계 체크포인트를 보존한다. 개발 평가만으로 일반적인 우위를 확정하지 않으며, 같은 설정의 무조건 추가 연장은 하지 않는다.

`runs/league_expanded_ppo_assess_20261008`에서 후속 대결을 실행한다. 개발 순위로 6900을 주후보로 고정하고, 6901·출발 PPO·순수 extend-right·CEM6800과 비교한다. 기존 134개 상대, 새 PPO 실행 변형 4개, 미학습 전환 규칙 8개를 상대로 새로운 102M 조건 4개를 양쪽 자리에서 수행한다. 확률 정책은 행동 난수 2개, 결정적 정책은 1개로 총 9,344경기다. 네 초기 조건의 비교는 탐색적이며, 유망한 결과에는 별도 조건 확인이 필요하다.

검증된 별도 실행 프로필의 16개 작업자(NumPy 14개·일반 2개)를 사용한다. 새 전환 규칙은 일반 작업자에 배정한다. 이전 학습·정책·공식 규칙은 보존하며, GitHub 업로드는 하지 않는다.

```powershell
$env:OPENBLAS_NUM_THREADS='1'
$env:OMP_NUM_THREADS='1'
$env:MKL_NUM_THREADS='1'
& '.venv-cpu\Scripts\python.exe' -X utf8 -u -m tools.league_expanded_ppo_assess --source runs/league_expanded_ppo_continue_20261008 --out runs/league_expanded_ppo_assess_20261008
```

새로 재현할 때는 비어 있는 출력 경로를 지정한다. 동결된 조건 예약과 기존 결과를 덮어쓰지 않는다.

## 후속 대결 완료

`league_expanded_ppo_assess_20261008`은 9,344경기, 종료 코드 0, `expanded_comparison_raw_verified`다. 실행 시간은 약 777초였다. 새 실행 조합의 정확한 과거 대비 배속을 측정한 것은 아니다.

| 상대 구분 | 새 PPO 6900 | 새 PPO 6901 | 출발 PPO | 순수 교사 | CEM6800 |
|---|---:|---:|---:|---:|---:|
| 기존 134개 | 83.54% | 83.26% | 82.84% | 83.96% | 85.91% |
| 새 PPO 변형 4개 | 31.25% | 29.69% | 29.69% | 28.13% | 31.25% |
| 미학습 전환 규칙 8개 | 30.47% | 39.84% | 20.31% | 23.44% | 32.81% |

6900의 기존 상대 승률 차이는 출발 PPO 대비 +0.70%p, 초기 조건·행동 난수 재표집 95% 구간은 -0.93~+2.52%p다. 미학습 전환 규칙 차이는 +10.16%p지만 구간은 -18.75~+46.88%p로 넓다. 개선 신호는 있지만 확정적인 전체 우위는 아니다. 두 모델 모두 기존 상대 하위 25% 점수는 출발 모델보다 나아졌다. CEM은 균등 상대 평균에서 여전히 강하므로 보존한다. 전환 규칙 패널은 이 시점부터 소비된 조건이며 이후 학습에 사용하면 미학습 증거로 재사용할 수 없다.

6900은 회피 봇에 16전 전부 시간 초과였고, 상대 평균 잔여 체력은 약 0.999다. 왼쪽 연장·왼쪽 지연 전술에는 각각 0승·11동시 격추·5패였다. 연장 전술 평균 종료 시점은 49.5초, 지연 전술은 74.1초다. 서로 다른 약점이며, 모두 장기 추격 실패로 묶지 않는다. 세부 기록은 `weakness_duration_diagnostic.json`이다.

다음은 동일 출발 PPO6900에서 물리 단계 할인율 0.999와 0.9999를 비교하는 제한된 학습 실험이다. 같은 난수·상대 분포·새 초기 조건·예산을 적용하고 두 학습 난수로 반복한다. 장기 승리 할인 감소가 유효한지 검증하며, 동시 격추 약점까지 해결한다고 전제하지 않는다. 원래 CEM과 모든 PPO 체크포인트를 유지하고, 무조건 연장하거나 전역 최고 정책으로 승격하지 않는다.

## 과거 중간 기록: 첫 반복 완료, 두 번째 진행

6900 반복은 3,932,160단계까지 학습했다. 같은 개발 조건의 시작 승률 61.71875%에서 첫 구간 65.234375%, 두 번째 66.015625%로 개선됐고, 최악 점수도 0.125에서 0.25로 올라 연장 조건을 충족했다. 세 번째 구간에서는 62.890625%로 낮아졌다. 따라서 **2,621,440단계 체크포인트를 유지**하며 마지막 가중치로 덮어쓰지 않는다. 6901 반복은 계속 진행 중이고 전체 배치 원시 검증은 아직 실행 전이다. 이 결과는 추가 학습이 항상 단조롭게 좋아지는 것은 아님을 보여주지만, 새 조건의 일반화 성능을 확정하지 않는다.

후속 후보 비교용으로 `experiments/league/switching_audit_20261008/panel.json`의 상대 8개를 고정했다. 알려진 순수 extend·두 CEM 정책 사이를 시간·거리·상대 선회·위협에 따라 바꾸는 **미학습 전환 규칙**이다. 구성 요소 자체는 기존에 노출됐으며 완전히 새로운 여덟 아키텍처나 실제 참가자로 표현하지 않는다. 공개 관측만 사용하고 모든 내부 제어기는 실제 관측으로 상태를 갱신한다. 원래 코드와 자체 포함 제출 파일의 19,200개 합성 관측·초기화 검사가 일치했다. **아직 실제 대결 결과는 관측하지 않았고 현재 PPO 학습에는 넣지 않았다.** 후보를 고정한 뒤 새 조건 평가에 사용할 계획이다.

## 선택 근거

`league_extend_parameter_assess_20261007`가 **10,720판, 종료 코드 0**으로 완료됐고 `raw_comparison_analysis.json` 검증을 통과했다. 100M 초기 조건 여덟 개·양 진영, 기존 132개 상대의 결과는 아래와 같다.

| 정책 | 상대 균등 승률 | 코드 계열 균등 승률 | 취약 사분위 점수 | 최악 상대 점수 |
|---|---:|---:|---:|---:|
| CEM 6800 | 85.0379% | 76.7175% | 0.6316 | 0.15625 |
| CEM 6801 | 83.7595% | 76.9031% | 0.6402 | 0.25 |
| 보존한 PPO 6700 | 83.7121% | 79.0807% | 0.6108 | 0.1875 |
| 순수 extend 제어기 | 83.2386% | 77.6218% | 0.6042 | 0.28125 |

CEM 6800의 PPO 대비 균등 승률 차이는 +1.3258%p지만 조건·행동 난수 재표집 구간은 **−0.3314~+3.2670%p**였다. 코드 계열 균등 차이는 −2.3632%p였고 구간은 −5.0950~+0.3743%p였다. 순수 제어기 대비 균등 승률은 +1.7992%p, 구간 +0.4261~+3.2197%p였다. 이는 고정 모델·상대와 여덟 초기 조건에 조건부인 비교이며 미래 대회 참가자를 대표하지 않는다.

CEM 6800은 오른쪽 초기 선회 상대에 2승 1무 13패였다. 동일 상대에서 PPO 두 행동 난수를 합치면 10승 11무 11패였다. 새 CEM 두 모델을 상대하는 별도 묶음에서도 CEM 6800 승률은 9.375%, PPO는 31.25%였다. CEM은 반응형 상대에 장점이 있지만 전역 모델을 교체할 만큼 일관되게 우월하지 않다. **모든 CEM·PPO·기준 제어기를 보존하고, PPO를 새 CEM들도 상대하도록 이어 학습한다.**

## 실제 후속 학습

실행 폴더: `runs/league_expanded_ppo_continue_20261008`.
실행기: `tools/league_expanded_ppo_continue.py`.

- 시작 체크포인트는 `runs/league_extend_entropy_train_20261007/prior6/s6700/checkpoints/step_1310720/learner.zip`이다. actor·critic·Adam 상태를 정확히 복원한다. 신경망을 처음부터 다시 만들지 않는다.
- 난수 6900/6901, 학습 조건 292M/293M으로 두 번 이어 학습한다. **같은 학습된 조상을 공유하는 조건부 반복**이며 독립적인 처음부터 학습이라고 부르지 않는다. 공통 1,310,720단계는 추가 학습량에 중복 집계하지 않는다.
- 기존 132개 상대와 새 CEM 후보 두 개, 총 134개 상대를 유지한다. 전체 순환과 가중 선택을 번갈아 사용해 실효 에피소드 선택 비중은 균등 70%·코드 계열 15%·관측된 약점 15%이다. 전이 수 비중은 아니다.
- 공개 관측과 공식 FairFight 물리·시작 조건·무기·행동·승패를 보존한다. 기준 제어기는 기존 extend-right이고, PPO prior6·ent_coef0·rollout640 등 설정을 유지한다.
- CPU 작업자 8개, 가상 환경 32개다. 시작·실행 중 메모리 보호 처리를 유지한다.
- 각 반복은 기본 **1,310,720단계 × 두 구간 = 2,621,440단계**이다. 두 반복 합계 기본 **5,242,880단계**이다.
- 두 번째 구간까지의 유지 후보가 첫 구간과 시작 정책보다 종합 순위 첫 값을 각각 0.005 이상 높이고, 취약 사분위·최악 점수도 초기/이전보다 낮지 않을 때만 한 구간 더 실행한다. 최대 합계 **7,864,320단계**이다. 초기·중간·최종 체크포인트를 보존하므로 마지막 가중치가 나쁘면 이전 모델을 유지한다.
- 새 101M 개발 조건 두 개·양 진영과 32개 상대에서 행동 난수 4900/4901로 비교한다. 초기 평가는 공유하고 각 구간 끝에서 평가한다. 기본 평가 1,280판, 모두 연장될 경우 1,792판이다. 100M 결과는 약점 선택에 소비됐고 101M도 개발용이며 최종/미사용 상대 시험이 아니다.

## 다음 대결 실행의 병목 개선

앞선 넓은 평가에서는 670개 대결 묶음 중 562개가 일반 작업자 4개로 몰렸고 NumPy 전용 작업자는 108개만 맡았다. 새 코드가 아직 승인되지 않았기 때문이다. 이전 실행의 설정과 기록은 수정하지 않았다.

`league_extend_numpy_qualification_20261007`는 검토한 새 PPO·CEM·반응형 세 코드 계열, 14개 정책 인스턴스에 대해 일반 실행과 분리 실행으로 **180판**을 실행했다. 공식 에피소드·요약·선택한 전체 피해 추적이 정확히 일치했고 NumPy 작업자에 Torch가 로드되지 않았다. 종료 코드 0, `sampled_numpy_execution_qualified`이다. DQN 및 미검토 history/hold/portfolio 계열은 일반 작업자에 남긴다.

같은 670개 묶음을 새 승인 목록으로 분류하면 NumPy 610개·일반 60개다. 새 대결용 설정은 `experiments/league/execution_profile_extend_20261008.json`에 별도로 저장한다. 기존 16개 작업자 벤치마크와 새 코드 호환성 검증을 근거로 이후 대결에서는 14 NumPy+2 일반 작업자를 사용할 수 있다. **새 정책 조합의 실제 속도 배수는 아직 측정하지 않았고, 현재 PPO 학습 작업자는 여전히 8개**다. 원래 전역 실행 프로필도 보존한다.

완료된 결과로 예산 연장·후속 학습을 판단하며, 유망 모델은 기존 정책들과 새 조건에서 대결시킨다. 더 강하고 약점이 적은 정책의 확인은 아직 진행 중이다. GitHub 업로드는 사용자가 명시적으로 요청할 때만 한다.
