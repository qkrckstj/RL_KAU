# 시간 관측 비교와 추가 학습

## 완료 결과와 후속 실행

추가 학습 네 분기는 총 4,194,304단계를 완료했고 종료 코드 0을 확인했다. `raw_budget_analysis.json`에서 원시 대결, 실제 PPO 설정, 정책 보존과 예산 검사를 통과했다.

| 방식 | 첫 반복 추가 학습 전 → 후 | 두 번째 반복 전 → 후 | 평균 전 → 후 |
|---|---|---|---|
| 단일 시점 | 54.69% → 67.97% | 64.06% → 61.72% | 59.38% → 64.84% |
| 시간 관측 | 67.19% → 52.34% | 57.81% → 58.59% | 62.50% → 55.47% |

시간 관측은 두 반복 모두 이전 선택 모델을 갱신하지 못했다. 같은 설정으로 더 늘리지 않는다. 단일 시점은 한 반복에서 회복했지만 다른 반복은 감소했으므로 안정적인 개선으로 확정하지 않는다. 상대 그룹 균등 평균 점수는 단일 시점 64.97% → 69.01%, 시간 관측 65.97% → 60.29%였다. 이 수치는 같은 개발 패널의 결과다.

후속 실행 `runs/league_history_transfer_assessment_20261007`을 시작했다. 개발 점수로 고정한 최선 단일 시점 후보와 최선 시간 관측 후보, 공통 시작 정책, 보존한 CEM을 각각 알려진 100상대와 대결시킨다. 새 조건 86M의 초기 조건 4개·양 진영·정책 행동 난수 두 개를 사용한다. 총 5,600판, 작업자 8개(일반 4개 포함)다. 시간 관측 소스는 NumPy 전용 실행을 검증하지 않았으므로 일반 작업자에서 실행한다. 역할 이름 `candidate`는 단일 시점, `warm`은 시간 관측, `early`는 공통 시작 정책을 뜻하며 과거 실행기의 역할 명칭과 혼동하지 않는다.

실행기 `tools/league_history_transfer_assess.py`는 기존 검증된 대결·집계 실행기에 새 동결 계획을 제공한다. 이는 새 초기 조건에서 알려진 상대에 대한 비교이며, 미사용 상대나 최종 평가를 대체하지 않는다. GitHub 업로드는 하지 않았다. 아래 중간 진행 기록의 실행 중 표시는 이 완료 결과로 대체된다.

PPO 설정을 일치시킨 비교가 4,194,304단계를 완료했으며 프로세스 종료 코드 0을 확인했다. 원시 대결 기록과 실제 로드된 설정 검사를 통과했다.

| 관측 | RNG6000 승률 | RNG6001 승률 | 평균 |
|---|---:|---:|---:|
| 현재 시점 | 54.69% | 64.06% | 59.38% |
| 현재 + 1초/5초 변화 | 67.19% | 57.81% | 62.50% |

시간 관측의 평균이 3.13%p 높지만 반복별 우열은 반대다. 시작 정책의 같은 개발 조건 승률은 65.63%였으므로 시간 관측이 안정적으로 개선됐다는 결론은 아직 내릴 수 없다. 기존 최선 모델은 보존한다.

후속 실행은 각 방식·반복의 마지막 105만 단계 가중치와 Adam 상태에서 추가 105만 단계씩 진행한다. 전체 추가 예산은 419만 단계다. 각 반복에서 양 방식에 같은 새 초기 조건 스트림을 사용하고 PPO 설정과 상대 분포를 유지한다. 이전에 선택된 더 좋은 정책은 후속 정책이 나빠져도 보존한다. 개발 조건 85M은 이미 사용된 조건이므로 후속 결과는 학습량 추세 점검이며 독립 일반화 검증이 아니다.

실행기: `aircombat-rl/tools/league_history_budget_extend.py`. 먼저 실제 학습·저장·복원 점검을 두 방식 각각 32,768단계 수행한 다음 본 실행을 시작한다. GitHub 업로드는 하지 않는다.

첫 단일 시점 반복은 추가 1,048,576단계를 완료했고, 같은 개발 패널의 승률이 54.69%에서 67.97%(174/256)로 회복됐다. 원시 기록에서 평가 점수를 다시 계산해 일치를 확인했다. 기존 선택 정책보다 점수도 높아 새 후보를 보존했다. 이는 첫 반복의 개발 결과이며 전체 전략의 개선 증거로 확정하지 않는다.

첫 시간 관측 반복도 추가 1,048,576단계를 완료했지만 승률은 67.19%에서 52.34%(134/256)로 감소했다. 원시 대결·저장 점수·실제 PPO 설정과 기존 정책 보존을 검사했다. 추가 학습 이전의 시간 관측 모델을 유지한다. 두 방식 모두 `temporal_extend_right`에 0승 8패였고, `evader`에는 8무승부였다. 단일 시점 모델의 회복이 이 취약점 해결을 뜻하지 않는다. 검증 기록은 `runs/league_history_budget_extend_20261007/first_repeat_raw_analysis.json`에 남겼다. 두 번째 반복까지 실행한 뒤 학습량 확대 여부를 판단한다.

두 번째 시간 관측 반복의 추가 학습도 완료했다. 승률은 57.81%에서 58.59%(150/256)로 소폭 변했고, 저장 평가 점수는 시작 정책보다 낮아 이전 선택 정책을 유지했다. 원시 대결 기록과 재계산 점수의 일치를 확인했다. 시간 관측 방식은 두 반복 모두 추가 학습으로 기존 최선 정책을 갱신하지 못했다. 같은 설정으로 시간 관측 학습량을 더 늘리는 근거는 부족하다. 마지막 단일 시점 반복이 실행 중이다.

전체 네 분기가 완료되면 `tools.league_history_budget_analysis`로 원시 대결, 실제 PPO 설정, 기존 정책 보존, 단계 예산을 검사한다. 방식별 두 반복의 평균·상대 그룹 균등 점수·취약 상대·반복별 방향을 함께 비교한다. 한 반복만 좋아졌다는 이유로 전체 학습량을 확대하지 않는다. 확대가 유망하면 다음 단계 전에 각 방식의 후보를 개발 점수로 고정하고, 새 초기 조건에서 기존 정책과 양 진영 대결을 수행한다. 그 결과로 후보를 다시 고르면 해당 평가도 이후 개발 자료로 취급한다. 실제 미사용 상대 평가와 최종 평가는 별도로 남겨야 하며, 알려진 100상대에 대한 높은 점수를 임의의 대회 참가자를 이길 증거로 해석하지 않는다.
