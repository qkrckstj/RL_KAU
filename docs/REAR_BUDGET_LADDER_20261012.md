# 고정 보상·상대 구성에서 학습량 확대

최근 정렬 잠재 보상, 상대 비중 단계화, 피격 계수1.0은 두 반복의 종합 개선을 보이지 않았다. 이 비교들은 주로 반복당655,360단계 후의 결과였다. 이를 장기 학습의 한계로 단정하지 않고, 기존 실제 후방 피해 .5 / 피격 .5 모델의 학습량 효과를 확인한다.

## 이어받는 모델과 예산

`league_tail_actual_reward_20261012/tail_s10100`과 `tail_s10101`의 actor/critic/Adam을 정확 복원한다. 기존 CEM/PPO/대조 체크포인트를 보존한다. 각 모델에655,360단계 두 구간을 추가해 반복당 새1,310,720단계, 두 반복 합계 새2,621,440단계를 수행한다. 후방 보상 실험의 최초 부모 이후 누적은 기존655,360 → 1,310,720 → 1,966,080단계다. 그 최초 부모가 이전에 받은 학습까지 모두 합친 생애 학습량이라는 뜻은 아니다.

보상 계수,48상대와 분포,quarter50%,gamma .999,prior6,PPO설정을 고정한다. 8작업자32환경과 메모리 보호 유지. 후속 에피소드에는445M/446M 대역을 사용한다. 기존 계획의 예약 대역을 확인하고 분리했으며 소비한 개발 평가 대역115M은 그대로다. 중단 당시 JSBSim 경기 상태는 직렬화되지 않아 시작 시 새 경기로 복원하는 것이고 정확한 중간 궤적 재개라고 부르지 않는다.

같은 실행의 두 구간은 모델과 환경을 닫지 않고 연속 학습한다. 체크포인트 내보내기 전후 learner 난수 상태를 보존하고 현재 관측·에피소드 시작 플래그·환경별 경기 번호 불변을 확인한다. 모델을 점검용으로 다시 로드하는 검사는 마지막 구간 후 수행한다. 단순 저장으로 이후 난수열을 바꾸지 않는다.

## 검증과 평가

별도 점검에서20,480단계 두 구간을 연속 실행하고 저장·복원을 확인한다. 본실험은 점검 모델이 아닌 원래 .5 체크포인트에서 다시 시작한다. 점검과 본실행 초기 대역이 겹치므로 점검을 독립 검증 성능으로 세지 않는다.

각 중간 모델은 행동 난수2×24상대×2초기조건×양좌석=192경기. 두 학습 반복×두 체크포인트=새768경기. 기존 대조384경기는 이미 검증된 정확히 같은 조건의 기록을 재사용한다. 총1,152비교 셀이며 새1,152경기를 돌리는 것이 아니다.

각 구간의 승률·실제 후방 피해·후방 사격권 체류·가한/받은 피해·정면 피격과 상대별 결과를 본다. 원래 대조와 직전 체크포인트를 모두 비교한다. Circler 외 여러 상대에서 후방 공격이 늘고 승률/피격을 유지하는 변화가 두 반복에서 나타날 때만 추가 예산·독립 반복·미사용 조건 확인으로 넘어간다. 한쪽만 좋아지거나 일반 승률만 오르면 후방 전술 성공으로 판단하지 않는다. 이번 실행의 자동 상한은 구간2개이며 에이전트가 완료 결과를 검토한 뒤 후속을 결정한다.

원래 FairFight 물리·무장·종료 및 round4 체력판정은 유지한다. 모든 모델·원시 경기·동결 입력을 보존하고 GitHub 업로드는 사용자 요청 때만 한다. 도구: `tools/league_rear_budget_experiment.py`, `tools/league_rear_budget_train.py`.

## 다음 가설: 지연 보상의 기여도 추정

확인한 후방계열 계획의 GAE lambda는 .99이고 현재 gamma는 .999다. 물리단계 .05초에서 GAE의 직접 TD잔차 가중치 `(gamma*lambda)^k`는20초(400단계) 뒤 약.01203이다. lambda .999면 약.44915다. 이는 종료/롤아웃 경계 전의 기하 가중치 비교이며,가치함수의 부트스트랩은더먼미래정보를전달할수있다. 이를4.5초짜리경성계획한계라고부르거나실패원인으로확정하지않는다. rollout640단계=32초라는경계도유지된다.

긴 진입 기동의 결과가 앞선 행동에 충분히 연결되지 않는 가설을 검토하기 위해 다음에는 GAE lambda .99→.999만 바꾸는 대응 비교를 준비한다. 보상,prior,상대/초기조건과 gamma는 유지한다. 추정분산이 커져 불안정해질 가능성도 있어 실제 성능과 업데이트 지표를 같이 확인해야 한다. 원래 .5 기준의 부모를 복원하며 본 예산확대 후보를 몰래 새 출발점으로 바꾸지 않는다. 새 실행은 아직 시작하지 않았다. Goal 미완료, 실행중 작업없음, GitHub 추가 업로드 없음.
