# 데스크톱 인계: 후방 전술 장기 학습과 비동기 평가 (2026-10-12)

## 현재 상태

이번 게시에는 후방계보 v2 계획, 출발 학습 체크포인트, 훈련 상대 48종과 개발 평가 상대 24종의 이식 가능한 입력을 포함한다. **새 장기 실행기와 비동기 평가 구조는 구현할 사양이며, 이미 작동하는 기능이 아니다.** 노트북에서 새 학습을 시작하지 않았다. 기존 스크립트는 참고 구현이고 과거 runs 경로에 의존할 수 있다.

- 우선 계획: [후방계보 v2](REAR_BRANCH_PLAN_20261012.md), [예산 사양](REAR_BRANCH_BUDGET_V2.json), [학습량 검토 근거](REAR_BUDGET_REVIEW_20261012.md).
- 부모: `aircombat-rl/experiments/league/rear_branch_20261012/rear_candidate/learner.zip` (`geometry_s10101`). 무작위 초기화가 아니다.
- 상대/교사/설정: `aircombat-rl/experiments/league/rear_desktop_20261012/inputs.json`. 정책 경로는 `aircombat-rl` 기준. 예산 문서 경로만 저장소 루트 기준으로 명시되어 있다.
- 기존 정면 교전 CEM/PPO와 모든 좋은 후방 체크포인트는 보존한다. 후방 후보를 승률 하락만으로 버리지 않는다.

## 데스크톱에서 시작

기존 작업 내용이 있으면 먼저 보존하고 저장소에서 `git pull --ff-only` 한다. Python 환경은 복사하지 않는다. 기존 데스크톱 학습 환경을 우선 사용하고, 새 환경이면 Python 3.12에서 가상환경을 만든 뒤 `aircombat-rl` 폴더에서 `python -m pip install -e ".[train,dev]"` 한다. 기존 GPU용 PyTorch를 임의로 CPU판으로 교체하지 않는다. JSBSim 버전과 재현 지침은 `REPRODUCE.md`를 따른다.

`aircombat-rl`에서 다음을 실행한다:

```powershell
python -m tools.verify_rear_branch_bundle
python -m tools.verify_rear_desktop_inputs
```

첫 검사는 공개한 두 경기 재현, 둘째는 상대 입력 해시와 정책 로딩을 확인한다. 기존 환경과 버전이 다르면 먼저 차이를 기록한다. 이 검사 통과는 장기 실행기가 구현됐거나 장기 학습 결과가 재현됐다는 뜻이 아니다.

## 적용할 구조: 학습 / 평가 / 분석·코드 검토 분리

1. **학습 프로세스 하나**가 고정 설정으로 계속 학습한다. 두 난수 반복은 각각 독립 실행 ID와 디렉터리를 가지며, 자원 확인 전에는 동시에 두 학습을 돌리지 않는다. 현재 기준은 학습 프로세스 8개·환경 32개이며 데스크톱에서 실제 자원 여유를 확인한다.
2. 학습은 655,360단계마다 새 이름의 체크포인트를 저장한다. 임시 디렉터리에 모델·최적화 상태·난수 상태·설정/코드 해시·실제 단계 수를 모두 기록하고 닫은 후, 완료 매니페스트를 원자적으로 게시한다. 평가자는 완료 표시가 없는 파일과 갱신 중인 로그를 읽지 않는다.
3. **별도 평가 프로세스**는 1,310,720단계마다 게시된 불변 체크포인트를 복사해 평가한다. 학습 프로세스의 메모리나 작업 디렉터리를 수정하지 않는다. 원격 복사도 수신 임시 디렉터리에서 해시 확인 후 완료 표시를 만든다. 체크포인트 ID와 평가 설정 해시로 중복 평가를 방지하고 실패한 평가는 재시도한다.
4. **분석 담당**은 완료된 평가 결과로 후방 공격량·지속 시간·피해·상대별 성능과 추세를 검토한다. **코드 검토 담당**은 별도 체크아웃/브랜치에서 변경안을 검토한다. 실행 중인 학습 코드, 보상, 상대 구성은 덮어쓰지 않는다. 수정은 검사를 통과한 뒤 다음 실행 구간 또는 다음 실험에 적용하고 변경 전후를 별도로 기록한다.
5. 평가가 늦어도 미리 승인된 고정 학습 예산 안에서는 학습을 계속한다. 평가 대기열이 쌓이면 불변 체크포인트를 보존하면서 중요 지점과 최신 지점을 우선한다. 평가 생략/지연은 명시하며 최소 예산 종료 판단에 필요한 지점은 반드시 평가한다.
6. 추가 5,242,880단계에 도달하면 필수 평가가 끝날 때까지 확장 판단을 기다린다. 근거 없이 무한 학습하지 않는다. 조건 충족 시 같은 설정으로 반복당 최대 추가 10,485,760단계까지 연장한다. 평가를 기다리는 정지는 허용되지만 중간 모니터마다 학습을 동기적으로 멈추지는 않는다.

가능하면 **데스크톱 학습 + 노트북 평가**로 자원 경쟁을 줄인다. 같은 컴퓨터에서는 학습용 CPU/메모리 여유를 우선 확보하고 평가 동시성을 제한한다. GPU만 보고 작업자를 정하지 말고 Windows 커밋 여유도 확인한다. 별도 프로세스는 실행기가 담당해야 하며 AI 대화가 계속 열려 있어야만 학습이 진행되는 구조를 만들지 않는다. AI 분석 호출은 완료 평가나 오류 같은 의미 있는 이벤트를 기준으로 한다.

## 예산과 의사결정

- 같은 부모에서 새 난수 2회, 각각 **추가 5,242,880단계**. 처음부터 재학습하지 않는다. 부모가 같으므로 독립 초기화 실험이라고 부르지 않는다.
- 보상·prior 6·quarter 50%·48종 상대·PPO 설정을 고정한다. 완료된 상대 강조 일정의 가중치 0을 유지한다.
- 모니터: 8상대 × 8초기조건 × 양 좌석 = 128경기/정책/지점. 부모 기준점을 한 번 평가하고 재사용한다. 예산 종료 개발 평가: 24상대 × 8초기조건 × 양 좌석 × 행동 난수 2회 = 768경기/정책.
- 학습/모니터/최종 평가 난수 대역과 조건은 실행 전에 확정·분리한다. 반복 사용한 평가를 미관측 최종 시험이라고 부르지 않는다.
- 최소 예산 전 승률 정체만으로 폐기하거나 보상 변경하지 않는다. 실제 후방 성과의 상승/유지와 피격 감소, 새로운 상대·초기조건으로의 확장을 본다. 자세한 예외·연장 조건은 v2 계획을 따른다.
- 수치 오류, 메모리 위험, 잘못된 승패/물리, 검증된 보상 악용, 사용자 중단은 안전 저장 후 정지 사유다. 재시작은 중복 실행 확인 후 수행한다. 실행 중 구간에는 환경/RNG/최적화 상태를 유지한다. 프로세스 재시작 시 JSBSim 에피소드는 새로 시작하며 완벽한 중간 궤적 복원이라고 주장하지 않는다.
- 보고: 추가/누적 실제 학습 단계, 학습 경기 수, 평가 경기 수, 학습 시간, 평가 시간, 전체 경과 시간, 처리량, 최고 메모리, 상대별 성과. 비동기 실행 시간은 겹치므로 학습 시간+평가 시간을 전체 경과 시간으로 합산하지 않는다.
- GitHub 업로드는 사용자 명시 요청 때만 한다.
