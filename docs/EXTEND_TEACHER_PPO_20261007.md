# 더 강한 기준 제어기로 새 PPO 학습

## 완료 결과와 후속 실행

### 엔트로피 비교 완료와 새 조건 평가

`league_extend_entropy_train_20261007`는 종료 코드 0으로 **2,621,440단계** 학습을 완료했고, 자동 원시 검증 및 `matched_entropy_analysis.json` 검증을 통과했다. 같은 초기 가중치와 조건의 첫 1,310,720단계끼리 비교했다.

| 학습 RNG | 기존 ent_coef 0.005 | ent_coef 0 | 차이 |
|---|---:|---:|---:|
| 6700 | 75.390625% | 79.296875% | +3.90625%p |
| 6701 | 77.734375% | 78.125% | +0.390625%p |
| 평균 | 76.5625% | 78.7109375% | +2.1484375%p |

두 실행 모두 대조군보다 취약 사분위 점수가 높고 최악 상대 점수가 0.125 개선됐다. 그러나 공통 시작 정책의 79.296875%를 평균으로 넘지 못했다. 6700은 시작 승률을 유지하며 최악 상대 점수가 개선됐고, 6701은 시작보다 낮았다. 두 실행 모두 자동 연장 기준에는 미달했다. **탐색 보상을 없애는 것이 이 개발 비교에서는 유리했지만, 학습 자체의 확실한 이득은 아직 입증하지 못했다.** 초기 정책을 버리거나 전역 정책을 승격하지 않았다.

후속 평가는 `runs/league_extend_transfer_v2_20261007`, 실행기 `tools/league_extend_transfer_v2.py`이다. 개발 순위로 미리 정한 6700 최종 모델, 다른 독립 학습 6701 최종 모델(초기 모델로 바꾸지 않음), 미학습 sampled prior6, 순수 extend 제어기를 비교한다. 앞의 세 정책에는 행동 난수 두 개를 사용한다. 기존 120개 상대, 새 학습 모델의 행동 변형 4개, 학습에 사용하지 않은 새 반응형 스크립트 8개를 대상으로 98M 초기 조건 네 개·양 진영에서 총 **7,392판**을 실행한다. 세 상대 묶음의 결과를 따로 보고한다.

새 상대는 `experiments/league/reactive_audit_20261007/panel.json`에서 첫 경기 전에 고정했다. 공개 관측만 사용하는 네 종류 휴리스틱의 두 설정씩이며, 실제 참가자나 독립적인 여덟 아키텍처·완전한 전술 공간이 아니다. 코드·가중치와 목록은 변경하지 않는다. 이후 이 상대를 학습에 쓰면 미사용 상대라고 부를 수 없다. 평가가 끝나면 원시 승패·짝지어진 조건·정책별 집계를 자동 검증한다.

첫 평가 시도 `league_extend_transfer_20261007`는 작업자 초기화 때 검증 모듈의 Torch import가 NumPy 전용 작업자에 섞여 종료 코드 1로 끝났다. **실제 대결은 0판**이며 소스·계획·실패 기록을 보존했다. v2는 검증 import를 평가 종료 후로 옮겼다. 깨끗한 import 검사와 기존 4,800판을 이용한 구분 집계 검사를 통과했으며, 새 98M 조건과 별도 출력 폴더로 실행한다. 실패 시 예약한 97M은 사용하지 않는다.

```powershell
& '.venv-cpu\Scripts\python.exe' -X utf8 -u -m tools.league_extend_transfer_v2 --source runs/league_extend_entropy_train_20261007 --out runs/league_extend_transfer_v2_20261007
```

이 평가에서도 학습 이득이 일관되지 않으면 순수 제어기를 보존하고, 저수준 PPO의 단순 연장 대신 이탈 시점·지속시간·추적 속도 등 전술 제어 파라미터 학습을 다음 분기로 검토한다. 최종 미사용 시험이나 모든 미래 참가자에 대한 우월성을 주장하지 않는다.

`league_extend_teacher_train_20261007`는 종료 코드 0으로 완료됐다. 실제 학습 **5,242,880단계**, 개발 평가 1,664판이며 `raw_extend_analysis.json`에서 원시 기록·설정·독립 초기화·선택·연장 결정을 검증했다. 네 실행 모두 취약 상대 성능을 포함한 연장 기준을 충족하지 못했다.

| 설정 | 초기 승률 | 학습 RNG 6700 | 학습 RNG 6701 | 두 학습 평균 |
|---|---:|---:|---:|---:|
| prior6 | 79.296875% | 75.390625% | 77.734375% | 76.5625% |
| prior8 | 76.953125% | 77.734375% | 77.34375% | 77.5390625% |

같은 개발 조건에서 순수 extend 제어기는 77.34375%였다. prior8의 평균 승률 증가는 작고, 두 반복 모두 취약 사분위 점수가 순수 제어기보다 낮았다. prior6은 두 반복 모두 초기 정책을 유지했고 prior8은 각 학습 후보를 해당 분기의 최고 기록으로 보존했지만, 전체 배포 정책으로 승격하지 않았다. 이전 120개 상대 평가의 88.02%와 이번 32개 개발 상대 점수는 평가 구성이 달라 직접 증감으로 해석하지 않는다.

학습 마지막 rollout의 평균 행동 엔트로피는 prior6/RNG6700에서 약 0.603, prior8/RNG6700·6701에서 약 0.101·0.086이었다. 초기 분포는 각각 약 0.136·0.024였다. 이는 행동 무작위성이 증가했다는 관측이며, 성능 하락의 원인을 확정하지 않는다.

후속 `runs/league_extend_entropy_train_20261007`는 **prior6의 ent_coef만 0.005에서 0으로 바꾸는 비교**이다. 실행기는 `tools/league_extend_entropy_train.py`이다. 같은 6700/6701 초기 actor·critic 텐서의 해시 일치와 나머지 PPO 설정 일치를 검사한다. 초기 optimizer는 모두 비어 있다. 기존 prior6 두 실행을 대조군으로 재사용하므로 다시 학습하지 않는다. 기준 제어기·120개 상대·선택 확률·학습 조건 난수 스트림·96M 개발 조건·행동 평가 난수·131만 단계 예산을 맞춘다. 행동 선택이 달라지면 실제 비행 경로도 달라진다. 확률적 행동 샘플링은 유지한다.

새 처리 두 실행의 기본 총량은 **2,621,440단계**, 두 실행 모두 연장될 경우 최대 5,242,880단계다. 이전과 같은 기준 제어기 및 취약 성능 보호 조건으로 연장한다. 96M은 이미 사용한 개발 조건이므로 미사용 시험이라고 주장하지 않는다. 이 비교가 끝나면 두 난수 각각의 대조군 대비 변화와 평균·취약 성능을 함께 확인한다. 원인 분리를 위한 개발 실험이며, 미사용 상대 검증과 전체 목표 완료는 여전히 남아 있다.

`league_extend_entropy_smoke_20261007`는 실제 20,480단계, 16판의 초기 greedy 제어기 동일성, 가중치 변화·optimizer 복원·설정·원시 평가 검사 후 종료 코드 0으로 완료됐다. 본 실행은 완료 시 원시 결과 분석을 자동 실행한다.


## 전체 상대 평가 결과

`runs/league_teacher_candidate_assessment_20261007`의 4,800판이 종료 코드 0으로 완료됐다. `raw_teacher_analysis.json`에서 원시 승패·진영·조건·집계를 재검증했다. 120개 상대, 새 95M 초기 조건 네 개와 양 진영이다. PPO는 행동 난수 두 개, 나머지 정책은 결정적 정책 하나이다.

| 정책 | 상대 균등 승률 | 코드 계열 균등 승률 | 취약 하위 사분위 점수 | 최악 상대 점수 |
|---|---:|---:|---:|---:|
| 기존 PPO | 68.3333% | 72.4250% | 0.3771 | 0 |
| extend_right | **88.0208%** | **81.6433%** | **0.6833** | **0.25** |
| extend_left | 47.7083% | 46.8714% | 0.1313 | 0 |
| 보존한 CEM | 42.5000% | 55.0680% | 0.1521 | 0 |

점수는 승리 1·무승부 0.5·패배 0이다. extend_right − PPO 승률 차이는 +19.6875%p이며, 조건·행동 난수 교차 재표집 구간은 +15.42~+26.98%p였다. 계열 균등 차이 +9.2183%p의 같은 구간은 +3.98~+15.93%p이다. 고정된 상대 목록·네 초기 조건·두 PPO 행동 난수에 조건부인 구간이며 임의의 미래 대회 참가자에 대한 확률은 아니다.

따라서 extend_right를 **새 학습의 고정 기준 제어기**로 사용한다. 이는 기존에 학습 상대로 쓰던 스크립트의 성능이지, 새 신경망이 이미 학습으로 달성한 성적이 아니다. 원래 CEM과 PPO, 모든 이전 결과는 보존한다. 최종 배포 정책 승격과 미사용 상대 시험은 아직 하지 않았다.

이 제어기의 약점은 반대 방향 extend, 지연 선회, 일부 속도 제어 정책이며 evader·circler에는 무승부가 많다. 이 결과에서 약점 가중치를 다시 계산한다. 현재부터 extend 계열은 평가 전용 상대가 아니라 학습에 사용한 정책으로 취급한다.

## 실제 본 학습

실행 경로는 `runs/league_extend_teacher_train_20261007`, 실행기는 `tools/league_extend_teacher_train.py`이다. 신경망은 기존 actor·critic·optimizer를 이어받지 않고 **6700/6701 난수로 새로 초기화**한다. 두 난수는 서로 다른 가중치 해시를 갖는다. 같은 난수의 두 prior 강도는 숨은 층과 critic의 초기 가중치를 공유해 비교한다.

정책은 39개 공개 관측을 받는 고정 extend 제어기와 40개 입력의 residual PPO를 함께 포함한다. 초기 residual 출력층은 정확히 0이므로 greedy 동작은 제어기와 같다. 이는 제어기를 포함하는 구조이며, 신경망이 제어기를 독립적으로 모방 학습했다는 뜻은 아니다. 샘플링 평가·학습에서는 행동이 달라질 수 있다.

- `prior6`: 초기 기준 행동 확률 약 98.06%.
- `prior8`: 초기 기준 행동 확률 약 99.73%.
- 각 방식에 독립 초기화 두 개, 고정 행동 난수 4900/4901로 평가한다. 행동 난수와 독립 학습 난수를 구분한다.
- 기존 120개 상대를 모두 유지한다. 전체 순환 방문과 가중 선택을 번갈아 사용하며, 실효 에피소드 선택 비중은 균등 70%·코드 계열 균등 15%·관측된 약점 15%이다. 전이 수 비중은 아니다.
- 공식 FairFight 초기 조건·물리·행동 공간·승패를 보존한다. 작업자 8개, 가상 환경 32개, rollout 640, gamma 0.999, GAE 0.99이다.
- 학습 조건은 288M/289M, 개발 조건은 96M이다. 초기 정책의 출력 분포가 같은 동일 prior끼리 초기 평가를 재사용한다. 실제 학습 초기 가중치는 각 난수의 것을 별도로 복원한다.

기본 예산은 실행당 1,310,720단계, 총 **5,242,880단계**이다. 첫 체크포인트의 종합 순위 첫 값이 **자기 초기 실행과 순수 extend 제어기 모두보다 0.005 이상 높고**, 취약 사분위·최악 상대 점수도 양쪽 기준보다 낮지 않을 때만 같은 분량을 한 번 더 학습한다. 모두 연장될 경우 최대 10,485,760단계이다. 이것은 초기값 대비 개선에 따른 연장이며 여러 체크포인트의 추세가 확인됐다고 표현하지 않는다. 두 개의 관련 조건 검사를 통과했다.

초기 `runs/league_extend_teacher_smoke_20261007`는 학습 전에 수치 검사에서 멈췄다. 32비트 확률 계산 차이가 2.384e-7이었고 행동 불일치는 0이었다. 실패 자료와 당시 소스는 보존했다. 수정된 검사는 초기 logits의 정확 일치와 64비트 확률 기준 대비 4×float32 epsilon 이내 오차를 확인한다. 초기 모델도 실제와 같은 32개 환경 형태로 생성한다.

`league_extend_teacher_smoke_v2_20261007`는 종료 코드 0으로 완료됐다. 원래 제어기와 초기 greedy 모델의 실제 32판이 완전히 일치했고, 두 설정 각각 20,480단계·총 40,960단계를 학습했다. 가중치 변화, actor·optimizer 저장 복원, PPO 설정과 원시 개발 결과를 검증했다. `raw_extend_analysis.json`에 결과를 남겼다. 작은 smoke 점수는 성능 주장의 근거로 사용하지 않는다.

## 재개 시 주의할 구체적 경로

현재 초기 모델은 `plan.json`의 **`warm_starts[arm][seed]`**와 `initializations`에 있다. 소스 체크포인트 단계는 0이다. 복사된 계획에 남은 단일 `warm_start` 필드는 이전 실행의 이력이며 이 실행에서는 사용하지 않는다. 이전 가중치와 새 초기 모델을 혼동하지 않는다.

```powershell
# aircombat-rl 디렉터리, OPENBLAS/OMP/MKL_NUM_THREADS를 모두 1로 먼저 설정
& '.venv-cpu\Scripts\python.exe' -X utf8 -u -m tools.league_extend_teacher_train --source runs/league_teacher_candidate_assessment_20261007 --out runs/league_extend_teacher_train_20261007
# 완료 후 원시 재검증
& '.venv-cpu\Scripts\python.exe' -X utf8 -m tools.league_extend_teacher_analysis runs/league_extend_teacher_train_20261007
```

기존 출력 경로로 중복 실행하지 않는다. 실제 프로세스와 completion/failure 파일을 먼저 확인한다. 실행 중 progress.json을 반복해서 읽지 않고 append-only telemetry와 완료된 체크포인트 결과를 사용한다. 새 결과에 따라 약점 학습·추가 학습량·다음 평가를 결정한다. GitHub 업로드는 자동화에서 제외한다.
