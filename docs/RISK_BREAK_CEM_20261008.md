# 상대 사격 위협에 따른 이탈 조건 학습

## 완료 결과

두 탐색은 각 33개 고유 매개변수를 평가했다. 총 9,880경기, 종료 코드 0, `risk_break_raw_verified`로 원시 경기·후보 생성·캐시·선택 검증을 통과했다.

첫 탐색 7200은 약0.29초 이탈 후보를 골랐으며 개발 승률56.25%, 기존 CEM은55.99%였다. 384경기에서 승리 한 번의 차이다. 두 번째 탐색 7201은 비활성화된 기존 정책을 그대로 선택했다. 첫 후보의 하위 25% 점수0.3385·최저 점수0.1875는 기존0.3333·0.125보다 높았지만, 두 탐색에서 재현된 개선이 아니므로 전술을 교체하거나 예산을 늘리지 않는다.

첫 탐색의 학습 조건에서 나타난 주요 승리 증가는 Ace 상대의 3승1패가 4승으로 바뀐 것이다. 목표였던 왼쪽 연장 상대의 동시 격추는 줄지 않았다. 긴 이탈은 일부 후보의 성능을 크게 악화시켰다. 이 결과가 모든 가능한 회피 전술의 실패를 증명하는 것은 아니다.

활성 후보는 이후 PPO가 상대할 새 정책으로 보존한다. 비활성화 후보는 이미 검증된 기존 CEM의 동등 구현이므로 가중치를 중복 부여하지 않는다. 다음 실험은 가장 최근 새 조건 비교에서 더 나았던 PPO7000을 이어 학습하며, 기존 상대 구성과 어려운 상대를 더 자주 선택하는 구성을 비교한다. 기존 체크포인트는 모두 남긴다.

새 조건의 3,840경기 비교에서 경기별 혼합 후보의 승률은 53.52%, 새 PPO7001·7000은 55.21%·56.38%, 출발 PPO는 54.17%였다. 이는 취약 상대를 포함한 48개 패널의 결과이며 전체 154개 상대의 승률이 아니다. 혼합으로 교체할 근거가 부족해 기존 모델을 모두 유지한다.

교사와 CEM6800은 자기 사격 기회가 있을 때 기존 이탈 동작을 억제한다. 새 PPO도 왼쪽 연장 상대에 0승·13무승부·3패를 기록했다. 이전 상세 기록에서 같은 계열 상대의 무승부가 주로 동시 격추였으므로, 사격을 유지하는 조건을 별도로 시험한다. 이 코드 조건이 약점의 원인이라는 인과관계는 아직 확인되지 않았다.

새 정책은 원래 CEM6800을 그대로 내부에서 실행한다. 상대의 공개 사격 가능 여부·조준 지속 시간·양측 잔여 체력을 보고, 학습된 조건에 해당하면 현재 기수 기준의 이탈 방향과 목표 속도로 잠시 행동을 바꾼다. 자기 사격 가능 여부로 이탈을 금지하지 않는다. 원래 제어기는 실제 관측을 계속 받아 내부 상태를 갱신한다. 비활성화하면 원래 행동을 그대로 반환한다.

학습 변수는 상대 조준 시간 기준, 체력 차이 기준, 이탈 지속 시간, 이탈 각도, 이탈 속도, 재발동 대기 시간의 6개다. 이탈 시간이 0이면 기능을 끈다. 내부에서 관측이나 공식 물리·무기·승패 판정을 변경하지 않는다. 공개 관측 39개 채널만 사용한다.

`tests/test_risk_break_policy.py`의 6개 검사를 통과했다. 비활성화 상태의 6,000개 연속 합성 행동은 원래 CEM과 같았고, 양측이 동시에 사격 기회를 가질 때도 발동할 수 있는지, 조건이 없으면 발동하지 않는지, 초기화·대기 시간을 검사했다. 각 실제 후보의 배포 코드도 원본과 120개 합성 행동을 비교한다. 실제 학습 시작 전 16경기에서 비활성화 정책과 기존 CEM의 에피소드·요약이 정확히 일치했다.

`runs/league_risk_break_train_20261008`에서 두 독립 CEM 탐색(7200·7201)을 실행한다. 각 4세대·10후보·상위 3개로 분포를 갱신하고, 세대마다 기본 정책과 현재 최고 정책을 유지한다. 이는 신경망 PPO 학습이 아니라 전술 변수 학습이다. 같은 고정 CEM6800 위에서 탐색 난수와 학습 초기 조건을 달리한 반복이다.

전체 156개 상대를 보존하며, 취약 상대와 서로 다른 코드 유형을 포함한 학습·개발 패널을 사용한다. 정확한 목록은 동결된 `plan.json`에 있다. 학습은 296M·297M 각 두 초기 조건을 양쪽 자리에서, 개발은 새 105M 네 초기 조건을 양쪽 자리에서 수행한다. 같은 매개변수와 학습 조건의 평가만 캐시로 재사용한다. 각 반복의 후보는 학습 결과로 먼저 고정한 뒤 개발 평가를 연다.

기존 CEM 탐색기와 평가 함수를 재사용하되, 새로운 드라이버·정책·검증기를 별도 파일로 둔다. 마지막 검증은 원시 경기, 후보 생성 난수, 캐시, 선택, 가중치 설정을 재계산한다. 비동기 합산 순서로 인한 미세한 부동소수점 차이에만 1e-12 허용 오차를 적용하고 정수 경기 수와 후보·선택은 정확히 검사한다. 이전 동결 소스는 수정하지 않는다.
