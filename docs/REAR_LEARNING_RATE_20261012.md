# 학습률 단독 비교

최근 보상·상대 비중·학습량·GAE 비교에서 여러 상대에 대한 후방 공격 전이가 확인되지 않았다. 이전 GAE 비교의 기록된 평균 KL 변화는 약.0004,clip 비율은 약1.3%였고 수치 오류는 없었다. 확인한 후방계열 계획48개는 학습률.0001이었다. 작은 업데이트가 실패 원인이라는 증명은 아니지만 다른 설정을 고정한 학습률 비교의 근거로 삼는다. target_KL .015는 도달 목표가 아니라 과도한 업데이트의 조기 종료 기준이다.

## 단일 변경과 복원

learning_rate .0001→.0003만 변경한다. 모델의 학습률,일정한 스케줄,옵티마이저 각 그룹을 함께 바꾸고 저장복원 후 일치를 확인한다. 정책/가치망 가중치와 Adam의 누적 모멘트는 원래 retained 부모에서 정확 복원한다. 직전 GAE 또는 예산확대 후보를 출발점으로 쓰지 않는다.

GAE .99,gamma .999,prior6,실제 후방 피해 .5,피격 .5,위치 .01 및 나머지 보상,48상대와 분포,quarter50%,rollout640,batch512,epochs4,clip.1,target_KL.015,기울기 제한 등은 그대로다. FairFight 물리·무장·종료와 round4 종료체력 승패를 유지한다. CPU8작업자32환경과 메모리 보호 및 해시 검사를 유지한다.

같은10100/10101학습 난수,소비한441M/442M훈련 대역,각655,360단계로 기존 대조와 비교한다. 새 학습1,310,720단계. 원래 대조 학습은 재사용한다. 원래 부모 기반의 대응 실험이며 독립 초기화나 미사용 최종 시험이라고 부르지 않는다.

## 검증과 평가

실제 원래 체크포인트를 이용해 가중치/Adam상태가 보존되고 옵티마이저 그룹의 lr만 바뀌는지,다른 PPO설정이 같은지,저장복원된 스케줄/그룹 lr가 .0003인지 검사했다.1개 통합검사 통과(8.27초). 별도20,480단계 실제학습 점검 후 본실행은 원래 부모에서 시작한다. 점검 초기 대역과 본실행은 겹치므로 점검은 성능 검증으로 세지 않는다.

새 평가384경기(후보2×행동난수2×24상대×초기조건2×양좌석),같은 조건의 검증된 대조384경기를 재사용한다. 총768비교 셀이며 개발 조건이다. 승률,실제 후방 피해와 유지 시간,가한/받은 피해,정면 피격 및 상대별 퇴행을 본다. 업데이트 KL/clip/가치 추정 로그도 함께 확인하며 큰 변화 자체를 성공으로 보지 않는다. 두 반복에서 다양한 상대에 대한 전이가 확인될 때만 추가 학습/독립 반복/미사용 조건 평가로 넘어간다.

기존 모델과 모든 후보 보존. GitHub 자동 업로드 없음. 실행 `tools/league_rear_lr_experiment.py`,훈련 `tools/league_rear_lr_train.py`,완료검토 `tools/league_rear_lr_review.py`,로그 진단 `tools/league_rear_lr_diagnostics.py`.

## 명령 지속성 추가 진단
