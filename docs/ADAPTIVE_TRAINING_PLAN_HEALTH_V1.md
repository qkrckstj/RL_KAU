# 종료 체력 기준 재판정과 적응형 자동 학습 계획

작성일: 2026-10-08. 상태: **기록 재집계·계획 작성 완료. 본 학습 정지 상태. 이 문서를 작성하는 것만으로 학습 프로세스나 Goal이 시작되지는 않는다.** GitHub 자동 업로드는 금지한다.

## 1. 목표와 판정 기준

사용자가 정정한 승패 기준을 우선한다. 기존 저장소의 판정을 과제의 공식 규칙이라고 단정했던 설명은 철회한다. 이 규칙은 `user_terminal_health_round4_v2`로 명시하며, 외부 대회 규정과 독립적으로 확인됐다고 표현하지 않는다.

- 기존 경기 종료 시점에서 양쪽 체력을 소수점 네 자리로 반올림한 뒤 비교한다. 내 체력이 높으면 승리, 낮으면 패배, 같으면 무승부다. 사용자가 반올림 동률은 그냥 무승부로 처리하도록 명시했다.
- 시간 종료 시 내 체력 80%, 상대 10%는 승리다.
- 상대 체력이 0이면 내 체력 1.5%든 3%든 양수인 쪽이 승리다. 기존 2% 생존자 무승부 문턱을 새 판정에 사용하지 않는다.
- 양쪽 체력이 반올림 후 모두0이면 무승부다. 아주 작은 실제 차이를 복구하기 위한 재생은 하지 않는다.
- 고정 고도, 물리, 초기조건 생성, 무장, 피해량, 의사결정 주기, 120초 제한과 기존 종료 시점은 유지한다. **승패 라벨과 그에 의존하는 학습·평가·선택 로직만 새 버전으로 맞춘다.**
- Python의 round(health, 4)를 양쪽에 동일하게 적용한다. 이외의2% 문턱이나 추가 동률 허용폭은 사용하지 않는다. 추후 사용자가 다른 규칙을 제공하면 새 버전을 만든다.

주목표는 다양한 상대에 대한 승률 향상이다. 체력 차이, 초반 피격, 경기 시간, 무승부율은 원인을 설명하는 보조 지표다. 무승부에 0.5점을 주던 내부 점수를 대회의 공식 배점이라고 부르지 않는다.

## 2. 먼저 할 일: 과거 경기 재판정

1. 기존 코드·원시 기록·가중치·구버전 결과는 그대로 보존한다. 기존 보고서에 새 승률을 덮어쓰지 않는다.
2. 로컬 `runs`의 JSON 경기 기록을 검색하고 출처 파일 해시, 구판정, 양측 종료 체력과 새 판정의 집계를 기록한다. 누락·오류는 별도로 표시한다. 소스 복사본은 제외한다. 원시 경기 없이 요약 승률만 남은 실험은 재판정 불가로 표시한다.
3. **4자리 반올림 체력이 서로 다르면 우열대로 판정하고 같으면 무승부로 확정한다.** 기존 `mutual`/`timeout` 이름을 그대로 새 결과로 쓰지 않는다.
4. 새 승률은 확정 승리 수/전체 정상 경기 수로 계산한다. 무승부도 분모에 포함한다. 체력 누락·범위 오류는 무승부로 위장하지 않고 별도 오류로 기록한다.
5. 복제된 JSON, 요약본과 원시본, 반복 재생을 새로운 독립 경기로 세지 않는다. 평가 패널별로 정책/가중치·상대·초기조건·진영·행동 난수를 식별한다. 같은 식별자의 기록이 다르면 충돌로 격리한다.
6. 초기 DQN/CEM/PPO부터 원시 기록 존재 여부를 목록화하되 서로 다른 상대·조건의 승률을 통합하거나 단일 순위로 정렬하지 않는다. 학습·개발·시험·smoke·성능 측정도 구분한다.
7. 반올림 동률을 확인하기 위한 재생은 중단한다. 이미 시작한 재생의 부분 결과는 보존하되 새 판정을 뒤집는 데 사용하지 않는다. 체력 누락이나 실제 기록 충돌 등 판단에 필요한 오류만 별도로 복구한다.

현재 실행 도구: `scripts/rejudge_health_records.py`. 최종 결과 폴더: `docs/health_rejudge_round4_20261008/`. 최신 패널은 `latest_panels.json`, 전체 기록 감사는 `all_records/summary.json`과 `all_records/file_inventory.csv`다. 전체 목록의 합계는 중복을 포함할 수 있는 기록 재고량이며 전체 승률이 아니다. 최신112M/113M 패널은 원본 `matches` 기록에서 동일 경기 식별자를 검사했다. 로컬 JSON103,231개를 확인해 경기 기록 파일92,740개의2,356,488개 기록을 재집계했으며 읽기/체력 오류는0건이었다. 기록 수에는 복제·여러 평가 단계가 포함돼 독립 경기 수나 총승률로 해석하지 않는다. 상세 결과는 [재판정 보고서](health_rejudge_round4_20261008/REPORT.md)를 따른다. `health_rejudge_20261008`과 부분 재생 폴더는 사용자의 동률 처리 지시 이전 자료로 보존하며 최신 기준 결과로 사용하지 않는다.

## 3. 출발 모델을 새로 선택

기존 PPO7400 유지/compact7800 보관/rotated7801 연구 후보라는 추천은 **구판정에 따른 역사적 판단**으로 둔다. 새 기준에서 같은 결론이 나오는지 확인하기 전에는 고정하지 않는다.

우선 비교 대상은 PPO7400, compact7800, rotated7801, CEM6800, 원래 보호 CEM, 현재 고정 교사 제어기다. 기존 동등 조건의 기록을 먼저 활용하고, 서로 다른 패널에만 존재하는 모델은 공통 조건의 소규모 비교를 추가한다. 세 PPO를 모두 다시 학습하지 않는다.

- 사용 경험이 있는 다양한 코드 계열과 주요 약점을 포함한 고정 개발 패널을 사용한다.
- 주 비교는 같은 상대·초기조건·양 진영에서 한다. 확률 정책은 사전 고정한 여러 행동 난수로 평가하며 이를 독립 학습 반복으로 세지 않는다.
- 각 정책의 평균 승률, 계열 균등 승률, 상대별 승률과 하위25% 성능을 보고한다. 전체 승률이 비슷할 때 취약 상대가 적은 정책을 선호한다.
- 상위 후보의 통계적 차이가 불확실하면 **초기조건을 추가**한다. 조건을 늘리지 않고 같은 소수 조건에 상대나 반복 기록만 늘려 확신을 키우지 않는다.
- CEM이 더 강하면 당장의 실행용 기준으로 보존하고 PPO 개선 실험과 분리한다. ‘최고 PPO’와 ‘전체 최선 정책’을 구분한다.
- 기존의 시험 결과를 보고 후보를 정했다면 해당 조건은 개발에 사용한 것으로 기록한다. 새로운 확인 평가를 나중에 별도로 둔다.

## 4. 학습 전에 끝낼 판정 일치 작업

동결된 구버전과 업로드된 복원 묶음을 수정하지 않고, 새 규칙 모듈·환경 래퍼·실행 폴더를 만든다. 학습 환경, 평가 도구, 체크포인트 선택기, 자동 연장 기준, 리플레이 표시가 **같은 판정 함수와 규칙 버전**을 사용해야 한다.

- `terminal_reason`(격추/양측 격추/시간 만료)과 `result`(승/무/패)를 분리한다. 시간이 만료됐다는 이유로 새 승리를 자동으로 무승부나 패배로 처리하면 안 된다.
- 시간 제한이 실제 경기 종료이면 PPO의 유한 에피소드 종료 처리와 potential의 종료값0을 유지한다. 결과 이름을 바꾸다 bootstrap 처리가 바뀌지 않게 검사한다.
- 정정한 세 예시, 반대 진영, 양쪽0, 같은 양의 체력, 미세한 체력 차이, 시간 만료를 모두 검사한다.
- 같은 고정 행동을 넣었을 때 원본과 새 래퍼의 궤적·피해·종료 시점은 같고 결과 라벨만 달라지는지 확인한다.
- 향후 원시 로그에는 반올림 전 체력과 판정에 사용한4자리 체력, 규칙 버전, 정책/소스 해시를 함께 저장한다. 실제 판정은 반드시4자리 값으로 통일한다.
- 실행 상태를 확인해 중복 실행을 막고, 소규모 실제 학습·저장·복원 검사를 통과한 뒤 본 학습을 시작한다.

## 5. 첫 학습: 판정 수정의 효과부터 확인

첫 단계에서 네트워크·교사·상대 구성·학습률까지 동시에 바꾸지 않는다. 재판정으로 선택한 PPO 출발점에서 두 학습 난수로 각각 약1,310,720단계씩 이어 학습한다. 시작 모델도 고정 대조군으로 평가하고 보존한다.

이 단계의 학습 보상은 기존 형태를 최대한 유지하되 **승패 입력을 새 판정으로 교체**한다.

- 새 승리: `+1 + 0.05 × 종료 시 내 체력`
- 새 패배: `−1`
- 4자리 반올림 동률: `0`
- 기존 potential 차이 보상은 유지하고 종료 potential은0으로 한다.

이는 순수 승률과 완전히 같은 목표가 아니다. 우선 라벨 오류 수정의 효과를 확인하기 위한 이행 실험이다. 체력 차이가 큰 시간 종료 승리를 보상하지 못하던 문제와 낮은 체력 생존 승리를 무승부로 처리하던 문제를 먼저 해소한다.

기존 critic과 optimizer는 구보상으로 학습됐음을 기록한다. 첫 구간의 적응 비용을 ‘보상 수정 실패’로 즉시 단정하지 않는다. 비정상 가치 추정이 반복되면 다음 실험에서 actor를 유지하고 critic 적응 방식을 별도로 비교하며, 몰래 초기화하지 않는다.

학습 상대는 우선48개 한도를 유지하되 **새 판정으로 계산한 약점**을 반영해 실행 전에 목록을 고정한다. 기존 전체 상대는 보관한다. 모델·보상·상대를 동시에 바꾸는 실험은 효과 분리 목적의 대조 실험이라고 주장하지 않는다.

## 6. 결과에 따라 자동으로 바꾸는 계획

각 구간 완료 후 실제 원시 결과와 구간별 학습 곡선을 읽고 아래 중 다음 행동을 하나 선택한다. ‘계획 수정’만 기록하고 끝내지 않고, 자동화가 실행 중인 경우 다음 실행까지 연결한다.

| 관측된 상태 | 자동 후속 행동 |
|---|---|
| 새 판정으로 학습한 두 반복에서 개선되고 주요 약점이 악화되지 않음 | 같은 설정으로 한 구간 연장. 연장 끝에 다시 판단하며 미리 여러 장기 작업을 예약하지 않음 |
| 개선 가능성은 있으나 평가 불확실성이 큼 | 새 학습 전에 기존 평가 패널의 초기조건/행동 반복을 보강. 유의미한 차이를 판별할 수준이 되거나 평가 예산 상한에 닿으면 결정 |
| 학습 보상은 좋아지지만 승률은 정체하거나 감소 | 종료 보상 목표 비교: 새판정 `+1/0/−1` 계열 대 승률 중심 `승1·무0·패0`. 체력 보너스 제거 등 여러 변경을 한꺼번에 하지 않고 정확한 차이를 명세 |
| 특정 상대에만 약하고 넓은 성능은 유지 |48개 중 최대8개를 같은 계열/약점 대표로 교체하거나 선택 비중 조정. 두 가지를 동시에 바꾸지 않음 |
| 학습 상대에서는 개선, 제외 상대에서 퇴행 | 기존 기준으로 복귀. 과거 상대 방문 비중/행동 유지 규제 중 한 가지만 별도 비교. 즉시 장기 연장하지 않음 |
| 공격 성과 없이 생존·시간 끌기만 증가 | 승리의 정의와 종료 보상 정합성 확인. 피해 억제 벌점을 추가하는 대신 승률 중심 보상 비교를 우선 |
| 승리는 늘지만 특정 상대에서 치명적인 약점이 커짐 | 후보는 보관하되 전면 승격 보류. 약점이 표본 잡음인지 확인 후 좁은 개선 실험 |
| 같은 변경이 두 학습 반복에서 퇴행하거나 두 구간 연속 정체 | 같은 설정 확대 중단. 가장 좋은 이전 모델에서 다음 가설로 전환 |
| PPO 추가 학습이 반복해서 강한 CEM을 넘지 못함 | CEM을 운영 기준으로 유지. 더 강한 교사 활용 또는 추격/이탈/재진입의 상위 전술 선택 중 하나를 새 실험으로 설계 |
| 메모리 부족/파일 잠금/비정상 종료 | 체크포인트·실패 사유 보존, 기존 안전 기준으로 대기·작업자 조정·재개. 같은 실패를 무한 재시작하지 않음 |

초기 제안 수치: 개발 평균 승률 +2%p 이상을 실용적 개선 신호로 보고, 상대 계열 균등 승률도 상승하며 하위25% 승률이3%p 넘게 악화되지 않는지 확인한다. 이는 과학적 상수가 아닌 운영 문턱이다. 불확실성은 초기조건과 행동 난수를 고려한 짝지은 분석으로 따로 보고한다. 두 학습 난수 평균으로 평가하되 한쪽의 큰 퇴행을 숨기지 않는다. 단일 최악 상대의 적은 경기 수 때문에 모든 개선을 자동 기각하지 않는다.

개발 신호가 좋은 경우에만 별도의 확인 조건으로 비교한다. 최종 승격은 새 기준 평균 승률의 개선 근거와 주요 약점의 비악화가 함께 있을 때 한다. 문턱을 바꾸면 **다음 실험부터** 적용하고 기존 실패를 소급 성공으로 바꾸지 않는다.

## 7. 평가와 자원 예산

- 매번 전체205상대를 평가하지 않는다. 고정 개발 패널 약24~40상대로 선별하고, 유망한 후보만 넓게 확인한다.
- 넓은 평가보다 먼저 공통 초기조건 수를 확보한다. 이전의2~4조건만으로 일반적인 대회 성능을 확정하지 않는다. 초기 개발은8~16조건·양 진영을 목표로 하되 실제 비용을 보고 다음 실행 전에 조정한다.
- 행동 난수는 우선2개로 시작하고 결과가 샘플링에 민감한 후보만 늘린다. 실제 제출이 greedy이면 sampled 성능을 그대로 제출 성능이라고 표시하지 않는다.
- 평가 비용은 원칙적으로 학습+평가 시간의 약20% 내외를 목표로 한다. 최초 규칙 교정·재판정·최종 확인은 예외로 따로 기록한다. 예산보다 판정 오류 검사가 우선이다.
- 노트북은 검증된 CPU 설정에서 시작한다.8개 실제 학습 작업자·32개 환경은 후보 설정이며 실행 전 현재 시스템 커밋 여유와 처리량을 확인한다. 평가용16작업자를 학습에 그대로 적용하지 않는다.
- 본 학습은 한 풀만 실행한다. 심한 자원 경쟁을 만드는 대규모 평가를 동시에 돌리지 않는다. 메모리 안전 기준은 완화하지 않는다.

## 8. 자동화 상태와 보고

상태 흐름: `과거 기록 재판정 → 누락/충돌 기록 점검 → 새 기준 출발점 선택 → 판정/보상 일치 검사 → 짧은 학습 → 개발 평가 → 연장 또는 가설 변경 → 별도 확인 → 후보 보존/승격`.

각 실행의 계획·원시 결과·분석·다음 결정을 별도 파일로 남긴다. 결정 기록에는 규칙 버전, 출발 가중치, 비교 대상, 이번에 바꾸는 한 요소, 학습/평가 예산, 근거, 불확실성, 다음 실행 명령, 중단/연장 조건을 포함한다. 상태 파일과 문서만 보고도 다음 에이전트가 중복 실행 없이 이어갈 수 있어야 한다.

사용자가 자동화 실행을 요청해 재개한 뒤에는 승인된 범위의 학습량 연장·상대 교체·가설 변경마다 다시 허락을 묻지 않는다. 다만 규칙 재변경, 원본 삭제, 외부 유료 자원 사용, GitHub 업로드는 자동 후속 행동에 포함하지 않는다.

한 프로세스가 끝났다고 자동으로 다음 분석이 실행되는 것은 아니다. 재개 시 실제 실행기와 Goal/후속 호출 연결을 확인한다. 현재 이 계획서는 실행 중인 자동화의 증거가 아니다.

보고 시점은 구간 완료·후보 승격·가설 변경·복구 불가 오류·사용자 조치 필요 시점이다. 변동 없는 상태를 반복 보고하지 않는다. 사용자 중지 요청은 항상 우선한다. 진행 중 저장 가능한 단위까지 정리하고 정지한다.

## 9. 이번 요청에서의 산출물과 남은 일

- 완료 대상으로 삼는 작업: 로컬 과거 JSON 기록의 재집계, 최신 공통 패널의 새 승률 산출, 이 계획서와 현재 상태 안내 갱신.
- 아직 완료라고 주장하지 않는 작업: 새 판정 환경 구현, 새 기준 최종 모델 선정, 새 보상 본 학습, 자동 실행기 연동.
- 기존 GitHub 커밋과 아카이브는 구판정 버전으로 보존한다. 사용자가 이번 계획서·재판정 결과의 업로드를 명시적으로 요청했다. 이번 한 번의 게시만 수행하며 향후 자동 업로드는 계속 금지한다.
