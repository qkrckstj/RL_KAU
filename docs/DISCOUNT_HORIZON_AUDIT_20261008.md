# 장기전 보상 할인 점검

## 완료 결과

`league_discount_train_20261008`은 총 5,242,880단계 학습을 마쳤으며 종료 코드 0, 원시 기록 및 동일 예산 비교 검증을 통과했다. 결과 전 기록한 분석 스크립트 해시도 일치했다.

| 설정 | 난수 7000 | 난수 7001 | 평균 |
|---|---:|---:|---:|
| 공통 출발 모델 | 54.29% | 54.29% | 54.29% |
| 기존 할인율 0.999 | 56.43% | 57.86% | 57.14% |
| 할인율 0.9999 | 54.29% | 53.93% | 54.11% |

0.9999는 두 난수 모두 통제군보다 낮고, 방법 연장 기준을 충족하지 않았다. 따라서 해당 변경을 채택하거나 일괄 연장하지 않는다. 통제군 7000은 하위 25% 점수가 0.3333에서 0.3056으로 내려갔고, 7001은 0.3472로 올랐다. 평균 개선만으로 모든 분기를 더 늘리지 않는다. 개발 순위가 높은 통제군 7001을 다음 새 조건 비교의 주 PPO 후보로 고정하고 7000도 함께 비교한다. 모든 가중치는 보존한다. 이 결과는 개발 평가이며 일반적인 우위를 입증하지 않는다.

후속 실행은 `league_mixture_screen_20261008`이다. 기록으로 가중치를 정한 경기별 혼합 후보와 두 통제 PPO·출발 PPO·두 원래 제어기를 비교한다. 공식 규칙과 기존 CEM은 그대로 유지한다.

현재 대결 평가를 변경하지 않고 코드와 수식을 확인한 기록이다. 결과 파일은 `aircombat-rl/runs/discount_horizon_audit_20261008.json`이다.

공식 의사결정 주기는 20Hz이고 제한 시간은 120초다. PPO와 학습 보상 래퍼는 물리 의사결정 한 단계마다 할인율 0.999를 사용한다. 승리 보상은 종료 시점에 발생한다. 에피소드 첫 상태에서 본 종료 보상의 할인 계수는 다음과 같다.

| 승리 시점 | 현재 0.999 | 실험 후보 0.9999 |
|---|---:|---:|
| 30초 | 0.5492 | 0.9419 |
| 60초 | 0.3013 | 0.8870 |
| 90초 | 0.1653 | 0.8353 |
| 120초 | 0.0907 | 0.7867 |

이는 늦은 승리의 보상이 작아진다는 수학적 사실이다. 현재 모델의 약점이나 성능 후퇴가 이 때문이라는 인과적 증거는 아니다. 조기 승리를 선호하는 효과와 패배를 늦추는 효과가 함께 존재하며, 할인율을 높이면 가치 추정의 어려움도 달라질 수 있다.

이전 `league_credit_horizon_train.py`는 롤아웃 길이와 GAE를 바꿨으며 물리 단계 할인율은 변경하지 않았다. 행동 유지 실험에서 할인율을 거듭제곱한 것은 결정 간격을 보정한 것으로, 실제 시간에 따른 할인 수준을 늘린 실험이 아니다.

후속 대결에서 장기전 약점이 확인되면 동일 출발 가중치·학습량·상대·조건을 사용하는 할인율 비교를 고려할 수 있다. 반드시 PPO, 롤아웃 버퍼, `gamma * Phi(next) - Phi(current)` 보상 래퍼를 함께 맞춰야 한다. 종료 시 Phi는 0을 유지한다. 공식 물리·초기 조건·시간 제한·승패 판정은 변경하지 않는다. 통제군과 처리군 모두 기존 actor/critic/Adam에서 출발한다면, 기존 할인율의 가치 추정기를 물려받는다는 한계도 기록해야 한다.

위 점검 시점에는 학습 설정을 변경하지 않았다. 이후 대결을 완료하고 아래 별도 실험을 시작했다.

## 후속 실험 실행

후속 대결 9,344경기의 원시 검증이 끝났다. 새 PPO는 소폭의 기존 상대 개선과 미학습 전환 상대 개선 신호가 있었지만 불확실성이 컸다. 회피 봇에는 16경기 모두 시간 초과, 왼쪽 연장·지연 전술에는 각각 11동시 격추·5패였다. 할인율이 이 모든 약점을 설명한다는 주장은 하지 않는다.

`league_discount_smoke_20261008`은 두 할인율에서 총 81,920단계를 실제 학습했고 종료 코드 0, `discount_raw_verified`다. 32개 실제 보상 래퍼·PPO·롤아웃 버퍼의 할인율 일치, 나머지 PPO 설정 보존, actor/critic/Adam 복원, 가중치 변화, 원시 개발 경기 검증을 통과했다.

본 실행은 `league_discount_train_20261008`이다. 출발 모델은 사전 개발 평가로 선택했던 PPO6900의 추가 2,621,440단계 체크포인트다. 같은 학습된 조상을 공유하며, 처음부터 독립 학습한 반복은 아니다. actor/critic/Adam을 그대로 복원하므로 0.9999 처리군은 기존 가치 추정기의 적응 비용도 포함한다.

- 설정: 0.999 대 0.9999, 두 학습 난수 7000·7001, 각 1,310,720단계, 총 5,242,880단계.
- 상대: 이전 134개·새 PPO 변형 4개·이번에 소비된 전환 규칙 8개, 총 146개. 양 설정이 동일한 상대 분포와 조건 스트림을 사용한다.
- 자원: 8개 실제 작업자, 32개 환경. 메모리 안전 기준과 대기 처리를 유지한다.
- 조건: 학습 294M·295M, 새 개발 103M. GAE 0.99·롤아웃 640·엔트로피 0 등 나머지 설정을 유지한다. gamma와 lambda의 곱도 약간 달라진다는 점을 해석에 포함한다.
- 예산: 한 구간씩만 실행하고 자동 연장하지 않는다. 완료한 모든 분기와 출발 정책을 비교한 뒤 추가 학습 여부를 결정한다. 기존 정책은 모두 보존한다.

본 학습의 첫 분기 결과가 나오기 전에 `matched_analysis_protocol.json`에 후속 분석 코드 해시와 기준을 기록했다. 완료 후 `tools.league_discount_matched_analysis`로 동일 예산의 최종 체크포인트를 비교한다. 보존된 초기 모델로 대체된 결과만 비교해 실제 학습 후퇴를 숨기지 않는다. 두 연속 학습 반복 모두 통제군·공통 출발 모델보다 승률이 0.5%p 이상 높고 하위 25%·최저 점수가 둘보다 낮지 않을 때 유망한 방법으로 분류한다. 통과하더라도 미사용 조건 및 독립 초기화 확인이 필요하며, 두 행동 난수를 독립 학습 횟수로 계산하지 않는다. 실행 전 기록된 스크립트 해시가 일치하는지 확인한다.

```powershell
$env:OPENBLAS_NUM_THREADS='1'
$env:OMP_NUM_THREADS='1'
$env:MKL_NUM_THREADS='1'
& '.venv-cpu\Scripts\python.exe' -X utf8 -u -m tools.league_discount_train --source runs/league_expanded_ppo_assess_20261008 --out runs/league_discount_train_20261008
```

실행 위치는 `aircombat-rl`이다. 같은 작업이 살아 있을 때 재실행하지 않는다. 새 실험을 재현할 때는 별도 출력 폴더와 미사용 조건 예약을 사용하며, 기존 동결 기록을 덮어쓰지 않는다. GitHub 업로드는 제외한다.
