## 앞선 선택기 결과

`league_portfolio_transfer_20261007`의 3,328판이 종료 코드 0으로 완료됐고 `raw_transfer_verification.json`으로 원시 결과를 재계산했다. 새 선택기의 승률은 65.6851%, 기존 PPO는 65.5649%였다. 차이 +0.12%p의 조건·행동 난수 교차 재표집 구간은 약 -4.93~+5.53%p로 0을 포함했다. 상대 코드 계열을 균등하게 보면 67.8387% 대 69.1761%로 새 선택기가 낮았다.

선택기 학습에 쓰인 13개 상대에서는 +3.85%p였지만 나머지 91개에서는 -0.41%p였다. 기반 전문가는 이 상대들을 학습한 적이 있으므로 91개를 완전히 미지의 상대라고 부르지 않는다. 기존 PPO를 유지하며, 선택기 개발 승률 상승을 일반적인 성능 개선으로 해석하지 않는다. 현재 CI는 네 초기 조건과 두 행동 난수·고정된 상대 목록에 한정된다.

## 행동 유지 사전 진단

`league_action_hold_probe_20261007`에서 같은 가중치로 행동을 1/5/10개 공식 단계 동안 유지했다. 물리 단계는 0.05초이며 상대는 매 단계 반응한다. 새 91M 조건 두 개·양 진영·행동 난수 두 개, 기존 상대 8개에 대해 각 방식 64판을 비교했다.

| 실행 방식 | 승리/64 |
|---|---:|
| 기존 0.05초 선택 | 27 |
| 0.25초 행동 유지 | 23 |
| 0.5초 행동 유지 | 16 |

192판과 포장 동일성 검사 16판이 완료됐으며 `raw_hold_verification.json`에 재검증을 남겼다. 단순히 실행 주기를 바꾸는 것은 개선이 아니었다. 이를 원인 확정이나 학습 후 성능 예측으로 사용하지 않는다.

## 실제 PPO 비교

`runs/league_hold_train_20261007`에서 기존 actor·critic·Adam을 복원하고 각 실행 주기에 맞춰 학습한다. 기존 CEM과 이전 모델, 104개 상대, 공식 초기 조건·물리·행동 공간·무기·승패는 보존한다.

| 항목 | control | hold5 |
|---|---:|---:|
| 결정당 공식 단계 | 1 | 5, 종료 시 즉시 중단 |
| 행동 선택 간격 | 0.05초 | 최대 0.25초 |
| PPO gamma | 0.999 | 0.999⁵ |
| GAE lambda | 0.99 | 0.99⁵ |
| 환경별 rollout 결정 수 | 640 | 128 |
| 한 반복 학습 결정 수 | 1,310,720 | 262,144 |
| 한 반복 실제 비행 단계 | 1,310,720 | 최대 1,310,720 |

5개 단계 보상은 `r0 + gamma*r1 + ...`로 누적한다. 상대와 교사는 모든 공식 단계에서 관측·반응한다. 전투가 도중에 끝나면 더 진행하지 않으므로 hold5의 실제 비행 단계는 상한보다 조금 작다. 이를 별도 기록한다. 같은 rollout의 최대 비행 시간은 32초이며, 두 방식 모두 본 학습은 64 rollouts다. 결정 수가 달라지므로 미니배치 학습 횟수도 다르다. 행동의 무작위성만 따로 바꾼 실험이라고 주장하지 않는다.

6500/6501 두 학습 난수, 두 방식의 순서를 반대로 반복한다. 286M/287M 공식 초기 조건 스트림과 별도 93M 개발 조건을 사용한다. 작업자는 8개, 가상 환경은 32개이다. 총 최대 **5,242,880 실제 비행 단계**이며 학습기 결정 수와 혼동하지 않는다. hold5는 실행 방식이 달라져 초기 행동도 다르므로 각 방식의 학습 전 기준과 공통 기존 PPO 기준을 모두 보고한다.

기본 종료·할인 보상·관측 갱신·초기화 검사 5개가 통과했다. `league_hold_smoke_20261007`에서 두 방식 각각 20,480 비행 단계, 총 40,960단계를 실제 학습했다. 가중치 갱신, actor·optimizer 정확 복원, 저장된 gamma/GAE/rollout 설정을 확인했고 `raw_hold_analysis.json`에 재검증했다. 추가 실제 비행 8회에서 반복 포장과 원래 환경의 관측·보상·체력·시계·승패가 완전히 일치했다(`real_physics_equivalence.json`).

실제 평가 정책은 체크포인트의 `sampled_4900`/`sampled_4901`이다. hold5의 기본 greedy export는 포장 전 보조 산출물이므로 실제 held 정책과 혼동하지 않는다. 제출·대결에는 실험에 명시된 sampled replica를 사용한다.

```powershell
# aircombat-rl 디렉터리. 세 스레드 환경 변수를 먼저 1로 설정한다.
& '.venv-cpu\Scripts\python.exe' -X utf8 -u -m tools.league_hold_train --source runs/league_action_hold_probe_20261007 --out runs/league_hold_train_20261007
# 완료한 뒤 원시 결과 재검증
& '.venv-cpu\Scripts\python.exe' -X utf8 -m tools.league_hold_analysis runs/league_hold_train_20261007
```

기존 출력 경로로 중복 실행하지 않는다. 재개 시 실제 프로세스와 완료/실패 파일을 확인한다. 읽기는 append-only `telemetry.jsonl`, `physical_telemetry.jsonl` 또는 완료된 결과를 사용하고, 실행 중 덮어쓰는 progress 파일을 반복해서 읽지 않는다. 결과를 보고 학습량 확대·집중 학습·다른 전략을 결정하며 자동 승격이나 GitHub 업로드는 하지 않는다.
