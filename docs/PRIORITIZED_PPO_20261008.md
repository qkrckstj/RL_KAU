# 어려운 상대 비중을 늘리는 PPO 연속 학습

## 완료 결과 및 후속 대결

후속 대결도 11,072경기 모두 완료했고, 원시 검증 및 재개 전 결과 해시 보존 검사가 통과했다. 기존 157개 상대의 평균 승률은 후보7300 **75.12%**, 반복7301 **73.69%**, 출발 PPO **73.85%**, 순수 교사 **72.77%**, CEM6800 **75.88%**였다. 후보의 출발 모델 대비 차이는 +1.27%p이나, 초기 조건·행동 난수 재표집 95% 구간은 약 -1.59~+3.98%p로 0을 포함한다. 코드 유형 균형 승률은 후보71.40%, 출발70.03%, CEM68.51%로 평균과 다른 순위를 보인다. 단일 지표만으로 우승 모델을 정하지 않는다.

새 체크포인트 상대의 후보 승률은25.39%, 출발17.58%였으나 불확실성이 크다. 이미 사용한 switching 상대는 후보와 출발 모두27.34%였다. 후보의 evader 결과는16무, extend-left는0승12무4패, delayed-left는1승12무3패, opening-right는4승7무5패였다. 회피 상대의 무승부와 일부 선회 상대 약점은 해결되지 않았다. 두 번째 반복에서는 개선이 재현되지 않아 정책 승격이나 성공 확정은 하지 않는다.

다음 실험은 학습률만1e-4 대2.5e-5로 비교한다. 동일한 개발 선택 후보7300에서 시작하고,173개 상대·동일 PPO 설정·공식 규칙·보상·예산을 유지한다. 기존 실험에서 두 번째 구간 성능이 반복적으로 하락했으므로 작은 업데이트가 이를 줄이는지 검증하는 가설이다. 개선을 보장하지 않으며 이 실험도 공유 조상의 연속 학습이다. 별도 보고서 `RATE_PPO_20261008.md`에 기록한다.

후속 대결 재개 기록: 기존 세션 84424와 컨트롤러 8428이 사라졌고 완료·실패 보고서는 없었다. 원인은 특정하지 않는다. 저장된 818개 묶음(6,544경기)을 기존 요청·승패 검증으로 확인하고, 설정과 소스 해시를 그대로 유지해 남은 566개 묶음을 `tools/league_prioritized_assessment_resume.py`로 재개했다. 기존 작업자 PID 중 하나는 Windows conhost가 재사용한 것으로 실행 파일 경로를 확인했으며 해당 프로세스에 손대지 않았다. 이전 런타임·작업자 정보 및 저장 결과 해시는 실행 폴더 `resume_attempts`에 보존했다. 재개 실행의 완료 시간은 재개 구간 시간이며 전체 원래 실행 시간을 뜻하지 않는다.

본 학습은 종료 코드 0으로 완료했다. `raw_prioritized_analysis.json`의 체크포인트·설정·실제 상대 선택 확률·승패·모델 보존·연장 판단 검증을 통과했다. 추가 학습은 총 **10,485,760단계**, 개발 평가는 **2,592경기**다. 네 분기 모두 연장 기준을 충족하지 않았다.

| 설정 | 첫 131만 단계 평균 승률 | 동일 예산 262만 단계 평균 승률 | 보존 모델 평균 승률 |
|---|---:|---:|---:|
| 기본 | 68.92% | 65.28% | 68.92% |
| 취약 상대 집중 | 66.15% | 66.32% | 67.71% (출발 모델) |

출발 모델은 67.71%였다. 기본 설정 두 반복은 각각 첫 구간 모델을 보존했고, 집중 설정 두 반복은 출발 모델을 보존했다. 집중 설정이 마지막 구간 평균에서는 기본 설정보다 높지만, 둘 다 출발 모델보다 낮으므로 이를 개선의 근거로 삼지 않는다. 같은 조상을 공유한 두 연속 학습 난수이며, 처음부터 독립적으로 학습한 반복이 아니다. 모든 후보는 보존한다. 수치와 입력 해시는 `matched_two_chunk_summary.json`에 기록했다.

새 초기 조건 107M에서 `runs/league_prioritized_ppo_assess_20261008` 대결을 시작했다. 개발 순위로 사전 선택한 기본 설정 두 모델, 출발 PPO, 순수 extend-right 제어기, CEM6800을 비교한다. 기존 157개 상대 전체와 새 학습 체크포인트 16개를 대상으로 초기 조건 네 개·양 좌석, 확률 정책당 행동 난수 두 개를 사용해 11,072경기를 실행한다. 기존 상대, 새 체크포인트, 이미 소비한 switching 상대 결과를 구분한다. 집중 설정의 보존 모델은 출발 모델과 같으므로 중복 실행하지 않는다.

실행기는 `tools/league_prioritized_ppo_assess.py`다. 기존 검증된 NumPy 로더 14개와 일반 로더 2개를 사용하고, 승인되지 않은 정책은 일반 로더로 보낸다. 신규 후보의 로더 소스 서명도 기존 승인 목록과 대조한다. 이 대결은 새 초기 조건의 성능 확인이며, 미지의 참가자 전체에 대한 검증이 아니다. 학습 연장은 중단했지만 Goal과 후속 실험은 계속한다. 결과가 옮겨가는지 확인한 후 독립 반복 또는 전략 변경을 결정한다. GitHub에는 업로드하지 않는다.

이탈 전술 CEM은 9,880경기 검증까지 완료했지만, 첫 탐색의 개발 승리 1회 증가가 두 번째에서 재현되지 않았다. 전술 교체는 하지 않는다. 별도 104M 대결에서 새 PPO7000은 48개 패널 승률56.38%, PPO7001은55.21%, 공통 출발 모델은54.17%였다. 이 소비된 비교를 이용해 PPO7000을 다음 학습의 출발점으로 선택한다. 새 조건에 대한 확정적인 우위나 전역 승격은 아니다.

원래 156개 상대와 활성 이탈 후보 하나, 총157개를 사용한다. 비활성 이탈 후보는 기존 CEM과 동등하므로 별도 상대 가중치를 추가하지 않고 파일만 보존한다. 기존 공식 물리·초기 조건·행동·무기·승패 규칙은 변경하지 않는다.

두 설정은 같은 actor/critic/Adam, 40개 입력 특징, 순수 extend-right 교사, 할인율0.999, GAE0.99, 엔트로피0, 롤아웃640으로 출발한다. 8개 실제 작업자에서 32개 환경을 실행한다. 학습 난수7300·7301 두 개를 사용하지만 같은 학습된 조상을 공유하므로 처음부터 독립 학습한 두 모델은 아니다.

| 설정 | 전체 상대 균등 | 코드 유형 균등 | 낮은 승률 상대 가중 |
|---|---:|---:|---:|
| 통제군 | 70% | 15% | 15%, 선형 |
| 우선 학습군 | 32.5% | 15% | 52.5%, 제곱 |

이는 에피소드 상대를 선택하는 비율이며 학습 전이나 실행 시간의 비율이 아니다. 통제군은 두 에피소드마다, 우선 학습군은 네 에피소드마다 전체 목록을 섞은 순서에서 상대를 고른다. 따라서 가중치와 전체 목록을 순회하는 빈도를 함께 바꾸는 실험이다. 둘 중 하나만의 효과라고 해석하지 않는다.

승률 추정은 `(승리+1)/(경기 수+2)`로 평활화한다. 현재 출발 모델의 104M 결과가 있으면 우선 사용한다. 없는 상대는 조상 PPO6900의 102M 결과를 명시적으로 표시해 사용하고, 새 상대는0.5 사전값을 쓴다. 낮은 승률 가중치는 통제군 `0.05 + 1 - 추정승률`, 처리군 `0.05 + (1 - 추정승률)^2`를 정규화한다. 조상의 약점을 현재 모델의 직접 측정으로 표현하지 않는다. 모든 상대에 양의 선택 확률을 유지한다.

각 설정·난수에1,310,720단계 구간 두 개를 배정해 기본10,485,760단계를 학습한다. 두 번째 구간의 보존된 순위가 첫 구간·출발점보다0.005 이상 개선되고 하위25%·최저 점수가 양쪽보다 낮지 않을 때만 같은 크기의 세 번째 구간을 추가한다. 최대15,728,640단계다. 모든 체크포인트를 남기고 마지막 가중치가 나쁘면 이전 최고를 유지한다.

학습은298M·299M의 짝지은 조건 스트림, 개발은 새106M 조건을 사용한다. 각 에피소드 길이가 달라지므로 같은 전이 시점마다 동일 상대·상태를 만난다는 뜻은 아니다. 출발 모델은 실제로5,242,880회 상호작용한 계보이며, 저장 파일의 카운터1,310,720과 구분해 기록한다. 기존 계보의 단계를 새 학습량으로 중복 합산하지 않는다.

`league_prioritized_ppo_smoke_20261008`에서 두 설정을 각각40,960단계, 총81,920단계 실제 학습했다. 종료 코드0, `prioritized_ppo_raw_verified`로 원래 파라미터·Adam 복원, 가중치 변화, 실제32개 환경의 상대 확률·순회 주기·보상 할인율, PPO 및 버퍼 설정, 저장·복원과 원시 개발 경기 검증을 통과했다. 이후 본 실행 `league_prioritized_ppo_train_20261008`을 시작했다.

```powershell
$env:OPENBLAS_NUM_THREADS='1'
$env:OMP_NUM_THREADS='1'
$env:MKL_NUM_THREADS='1'
& '.venv-cpu\Scripts\python.exe' -X utf8 -u -m tools.league_prioritized_ppo_train --source runs/league_risk_break_train_20261008 --out runs/league_prioritized_ppo_train_20261008
```

`aircombat-rl`에서 실행하며, 현재 실행을 중복 시작하지 않는다. 재현에는 별도 출력과 미사용 조건 예약을 사용한다. 원시 검증기가 학습 종료 후 자동 실행된다. 설정별 효과는 같은 두 구간 예산에서 비교하고, 추가 구간은 예산 연장 결과로 별도 해석한다. 기존 CEM/PPO와 동결된 파일을 보존하며 GitHub 업로드는 하지 않는다.
