# 지연 보상 연결: GAE lambda 단독 비교

이전 예산 확대는 새2,621,440단계를 추가했지만 두 반복의 승률 추세가 달랐고 최종 정책 모두 Circler 외 후방 피해가 없었다. 동일 설정을 더 오래 돌리는 대신 앞선 기동에 후속 결과를 연결하는 추정 설정을 비교한다.

## 근거와 한계

현재 설치된 Stable Baselines3의 `common/buffers.py`에서 GAE 계산을 확인했다. 연속 구간에서 TD잔차의 직접 가중치는 `(gamma*lambda)^k`이고 종료/에피소드 시작 마스크가 다음 경기로의 전달을 차단한다. gamma .999,물리단계 .05초,lambda .99일 때20초 뒤 잔차 가중치는 약.01203이며 lambda .999에서는 약.44915다.

이는 실제 실패 원인에 대한 증명이 아니다. 가치함수 부트스트랩은 더 먼 미래 정보를 전달할 수 있으며 rollout640단계(32초) 및 에피소드 경계도 있다. 더 큰 lambda는 추정 분산을 키울 수 있어 성능 악화도 가능하다. 4.5초짜리 경성 계획 한계가 있다고 표현하지 않는다.

## 실험

GAE lambda .99→.999만 바꾼다. `model.gae_lambda`와`rollout_buffer.gae_lambda` 모두 적용하고 저장 후 복원 값도 검사한다. 모델 정책/가치망/Adam은 원래 retained 부모로 복원한다. 직전 예산확대 모델을 출발점으로 쓰지 않는다. 같은10100/10101학습 난수,소비한441M/442M훈련 대역,각655,360단계로 기존 .99 대조와 대응 비교한다. 새 학습 합계1,310,720단계.

gamma .999,prior6,위치 .01,실제 후방 피해 .5,피격 .5 등 보상과48상대/분포,quarter50%,PPO 나머지 설정 유지. FairFight 물리·무장·종료와 round4 종료체력 승패를 보존한다. CPU8작업자32환경,시작/런타임 메모리 보호 및 동결 해시 검사 유지.

## 검증·평가

실제 원래 체크포인트로 설정 단독 변경 전후 가중치/Adam/기타 설정 일치와 저장복원,640단계 실제 SB3 버퍼에서 지연 잔차 가중치 및 경기 경계 차단을 검사했다.3개 검사 통과(8.36초). 별도20,480단계 실학습 점검을 하고 본실행은 원래 부모에서 시작한다. 점검 대역과 본학습 대역은 겹치며 독립 성능 검증이 아니다.

새후보2개×행동난수2개×24상대×2초기조건×양좌석=새384평가 경기. 정확히 같은 조건에서 이미 검증된 기존대조384경기를 재사용한다. 총768비교 셀이며 새768경기를 실행한 것이 아니다. 개발 조건 재사용이며 독립 최종 시험은 남겨 둔다.

승률,상대별 실제 후방 피해와 후방 사격권 체류,가한/받은 피해,정면 피해를 본다. 두 반복의 일관성과 Circler 외 여러 상대 전이가 있어야 추가 확인 후보로 삼는다. 작은 수치 변화만으로 승격하지 않는다. PPO 업데이트 KL/clip 및 가치추정 진단도 함께 확인한다. 기존 모델 보존,GitHub 자동 업로드 없음.

실행 도구: `tools/league_rear_gae_experiment.py`, `tools/league_rear_gae_train.py`. 완료검토: `tools/league_rear_gae_review.py`.

## 완료 결과: .999 미채택

본 실행28394/검토90454 종료0,업데이트 로그 집계 완료. 새 학습1,310,720단계·완료1,368훈련경기·259.70초. 신규 평가384경기+기존대조384경기 재사용,평가57.69초,전체431.15초(7분11초). 별도20,480단계 점검은 제외한다.

반복 간 승률/피격 방향이 엇갈리며 여러 상대에 후방 전이가 나타나지 않았다. GAE .999를 채택하거나 같은 설정을 장기 연장하지 않고 .99를 보존한다. 768정확한 셀,종료체력 판정,기존대조 일치,부모/Adam복원,GAE 적용/복원 및 해시 검사를 통과했다. 개발 조건 결과이며 미사용 최종 시험은 아니다.

후보 평균 approx_KL은 .000424/.000381,최대 .000756/.000542,평균 clip 비율은 .01366/.01321이었다. 검사한31개 업데이트 로그 값에는 비유한 값이 없었다. 평균 explained variance는 .673/.692로 대조 .906/.915보다 낮았지만 lambda 변경으로 추정 대상도 달라 직접적인 원인 증명은 아니다. SB3 로그는 마지막 실제 업데이트를 포함하지 않을 수 있으며 전체 학습 안정성의 수학적 보증은 아니다.

다음 가설은 업데이트 크기다. 확인한48개의 후방계열 계획은 learning_rate .0001이었다. 낮은 approx_KL/clip비율만으로 학습률 부족을 확정할 수 없고 target_KL .015는 달성해야 할 목표가 아니라 조기 중단 기준이다. 이를 구분하면서 원래 GAE .99·보상·상대 구성에서 learning_rate .0001→.0003만 바꾸는 대응 비교를 준비한다. 초기 가중치/Adam 모멘트 보존,학습률 스케줄과 optimizer 파라미터 그룹의 일치,과도한 업데이트와 성능 퇴행을 검사해야 한다. 새 실험은 아직 시작하지 않았다.
