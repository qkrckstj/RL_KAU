# 후방 진입 자동 학습 전략 — 2026-10-12

## 목적과 현재 상태

최종 목표는 다양한 정책을 이기는 동시에 정면 피해 교환을 줄이고, 후방 진입·지속 추적·일방적인 공격을 하는 정책이다. 현재 후방 전술 학습은 **검증 중**이다. 기존 CEM6800을 대체할 개선은 아직 확인하지 못했다. 논문을 모델 입력으로 넣는 방식이 아니라, 논문에서 가져온 설계를 코드와 훈련 조건으로 구현한다.

이 문서는 현재 전략·근거·후속 판단을 공개한다. 이번 업로드의 논문 PDF는 사용자가 제공한 원본이다. 로컬 실행 체크포인트와 전체 경기 기록은 이 문서만으로 복원되지 않는다. 아래 실행에는 해당 출발 체크포인트·동결 계획·상대 정책이 필요하다. 과거 저장소 아카이브를 복원했다고 최신 로컬 실행까지 복원됐다고 가정하지 않는다.

## 최신 전략 업데이트 — 할인율 연장 평가 단계

이 절이 아래 과거 위치 보상 단계의 “현재” 상태를 대체한다. 문서 게시 시점에 `league_tail_discount_extend_20261012`는 네 후보 학습을 마치고 평가 중이다. 종료 결과는 아직 확정하지 않는다.

### 지금 실행하는 방식

1. 기존 학습된 PPO에 성공적인 추적 시범을 모방시키되, 기존 상대를 상대할 때의 행동 분포를 유지하는 KL 제약을 더했다. 모델을 무작위로 다시 시작하지 않는다. CEM과 모든 이전 정책은 보존한다.
2. 시범 후보 두 개에서 같은 출발 가중치·critic·Adam을 복원하여 할인율 0.999 대 0.9997만 비교했다. 환경의 잠재함수 보상과 PPO/buffer 할인율도 일치시킨다. 48상대, 후측방 시작 50%·원래 시작 50%, 보상 계수는 고정한다.
3. 첫 비교는 총 2,621,440단계·1,536평가 경기였다. 대조군 평균 승률 70.57%, 긴 할인율 후보 72.79%였지만, 학습 전 시범 후보를 일관되게 넘지는 못했다. 후방 행동은 대부분 circler에 집중됐다. 새로운 최고 모델로 채택하지 않았다.
4. 현재는 각 갈래의 자기 체크포인트에서 655,360단계씩, 총 2,621,440단계를 한 차례 더 학습한 뒤 같은 개발 패널 1,536경기를 평가한다. 작업자 8개·환경 32개다. 새 학습 난수와 새 훈련 초기조건을 쓰며 중단 궤적의 정확 재개라는 뜻은 아니다.
5. 완료 후 현재 대조군뿐 아니라 첫 분량과 최초 시범 부모를 함께 비교한다. 추세가 없으면 같은 분량을 무조건 반복하지 않고 다음 한 요인을 선택한다. 후측방 시작 비율 조정은 검토 후보이며 아직 채택한 설정이 아니다.

### 지표 정정과 판단 기준

`tail_attack_seconds`는 **후방에서 사격 가능한 범위에 머문 시간**이다. 실제 사격 피해에는 연속 1초 추적 조건이 필요하므로 이를 실제 후방 피해 시간이라고 부르지 않는다. 기존 결과의 “후방 사격” 표현은 이 의미로 정정한다. 체력 승패 결과 자체가 바뀐 것은 아니다.

다음 진단은 매 물리 단계의 이동 후 기하와 정확한 체력 감소를 결합하여 실제 후방 피해량·피해 발생 시간·받은 피해를 구분한다. 진단은 학습 보상이나 물리를 바꾸지 않는다. 승률·실제 피해·다양한 상대 전이를 함께 확인해야 개선으로 판단한다.

### 검증된 범위와 실패에서 얻은 판단

- 모방만 강화하면 다른 상대 성능을 잃을 수 있어 기존 행동 유지 제약을 사용했다. 보존된 시범 후보도 새 조건에서 확실한 종합 우위를 보이지 않았다.
- 후보가 직접 방문한 상태에 CEM 행동을 라벨링하는 DAgger 방식의 소규모 실험은 특정 weave 상대를 개선했지만 다른 상대에서 손실이 생겨 전체 개선으로 채택하지 않았다.
- 고정 행동 선택 비교 역시 CEM을 대체할 근거가 되지 않았다. 개발 패널과 이미 본 새 조건을 미사용 최종 시험으로 부르지 않는다.
- 검증용 모델 로드가 전역 난수를 재설정하는 문제를 확인해 v2 실행기에서는 로드 후 실제 학습 난수를 다시 설정·검사한다. 과거 실행을 완전히 독립된 신경망 난수 반복으로 단정하지 않는다.
- 자동화는 실행기의 학습·평가·저장·검사와 Goal 에이전트의 결과 분석·다음 실험 선택으로 구성된다. 독립 실행기 하나가 무한히 전략을 변경하는 구조는 아니다. GitHub 업로드는 별도 명시 요청 때만 한다.

첫 할인율 비교 시간은 학습 508.61초, 평가 183.98초, 준비·저장 등을 포함한 전체 908.08초였다. 상세 설계와 결과는 [할인율 비교](TAIL_DISCOUNT_PLAN_20261012.md), [시범 유지 결과](TAIL_RETENTION_RESULTS_20261012.md), [다양한 시범/DAgger 탐색](TAIL_DIVERSE_DEMONSTRATIONS_20261012.md)에 있다.

이번 공개 범위는 전략·논문·결과 요약이다. 최신 로컬 체크포인트, 전체 원시 경기 및 실행 코드 의존성을 묶은 재실행 패키지는 포함하지 않는다. 따라서 이 업데이트만으로 최신 실행을 다른 컴퓨터에서 그대로 재개할 수 있다고 주장하지 않는다.

## 과거 실험: 학습된 모델을 이어받아 연속 위치 보상 추가

출발점은 `league_tail_curriculum_20261011`의 `s9100`, `s9101`이다. 각 출발점에서 actor·critic·Adam 상태를 정확히 복원하고 다음 두 갈래를 비교한다.

| 조건 | 기존 보상·후방 시작 비율·48상대·PPO | 새 위치 보상 |
|---|---|---|
| 대조군 | 동일하게 유지 | 0 |
| 실험군 | 동일하게 유지 | 위치 점수 × 초당 0.01 |

각 갈래는 655,360단계다. 두 출발점 × 두 갈래로 총 2,621,440단계를 추가한다. 출발점은 과거 공통 조상을 공유하며, 처음부터 독립 학습한 네 모델이라는 뜻이 아니다. 같은 쌍은 같은 난수·초기조건 스트림을 사용한다. 새 학습 초기조건 예약은 422M/423M이다.

위치 점수는 Pope 등의 PDF 5쪽 식(10)을 참고한다. 내 기수가 상대를 향하는 각도와 내가 상대 꼬리 쪽에 있는 각도를 조합한다. 프로젝트에서 별도로 `1/(1+(거리/4000m)^2)`를 곱한다. 기존 추가 잠재함수는 정면이나 4km 밖에서 0이었지만, 새 점수는 이 구간에서도 방향 차이를 구분한다. 점수 범위는 −1~1이다. 0.05초 간격의 추가 보상 절댓값은 최대 0.0005이고, 120초 누적 절댓값은 최대 1.2다.

이는 **최적 정책을 보존하는 잠재함수 차이 보상이 아니라 목적을 추가하는 직접 보상**이다. 따라서 승리보다 위치 유지에 집착하거나 공격을 미루는 부작용도 검사한다. 거리 감쇠와 계수는 논문 그대로가 아닌 우리 설계다. 체력·사거리·3D 비행을 논문 설정으로 바꾸지 않는다.

## 평가와 자동 후속 판단

원래 FairFight의 같은 24상대 × 4초기조건 × 양 좌석 × 행동 난수 2개를 사용한다. 네 후보 합계 1,536경기다. 115M 개발 조건은 이미 사용했으므로 미사용 시험으로 부르지 않는다. 저장한 원시 경기에서 체력 승패, 피해, 후방 시간과 요약을 재계산하고 같은 출발 가중치·동일 추가 학습량을 검사한다.

1. 승률이 대조군보다 2%p 넘게 떨어지지 않고, 평균 후방 사격권 체류가 0.5초 이상 증가하며 받은 피해 증가가 0.02 이하인 경우 연장 후보로 본다. 두 반복과 상대별 결과를 함께 확인한다. 이 수치는 탐색 기준이며 개선 확정이 아니다.
2. 위치 시간만 늘고 공격·승률이 악화되면 직접 보상 계수를 낮춘다. 경기 시간과 영상을 확인하여 공격 지연을 구분한다.
3. 후방 시작에서만 좋아지고 FairFight 전이가 없으면 측면/측후방 시작 난이도를 한 단계 바꾼다. 보상과 난이도를 동시에 바꾸지 않는다.
4. 어느 지표도 움직이지 않으면 무조건 장기 학습하지 않는다. 실제 지급 보상, 행동 변화, 조준·접근 속도 분포를 먼저 확인한다. 다음 후보는 논문의 접근 속도/과도한 접근 방지 항이나 별도 위치 확보 정책이다. 아직 구현된 기능으로 표현하지 않는다.
5. 유망한 후보만 추가 난수 반복과 학습·선정에 쓰지 않은 초기조건/상대에서 검증한다. 개발 패널의 반복 개선만으로 채택하지 않는다. 고정 경기 영상으로 정면 교환과 후방 추적을 확인한다.

실행기는 학습·평가·저장·원시 결과 검사를 수행한다. **후속 전략 선택과 다음 실행 연결은 활성 Goal 에이전트가 담당한다.** 에이전트 없이 실행기 하나만 켜 두면 무한히 전략을 바꾸며 계속 학습하는 구조는 아니다. 별도 5분 주기 자동화는 사용자 요청으로 일시 중지되어 있다.

매 주기에는 추가 학습 단계, 완료 학습 경기 수, 평가 경기 수, 순수 학습/평가 시간, 가능하면 초기화 등을 포함한 실제 전체 시간도 보고한다. 실행 중인 PID만 보고 학습 완료로 기록하지 않고, 종료 코드·완료 파일·원시 감사 결과를 확인한다.

## 실행 위치와 재현 전제

현재 로컬 구현: `experiments/league/tail_position_reward.py`, `tools/league_tail_position_train.py`, `tools/league_tail_position_experiment.py` (모두 `aircombat-rl` 아래). 기존 학습/평가 코드와 동결 입력을 보존한다. 새 실행 폴더·예약 대역을 사용하며 살아 있는 기존 프로세스를 중복 실행하지 않는다.

본 실험 명령은 `aircombat-rl`에서 실행한다. 아직 출발 모델 파일이 없는 새 복제본에서 그대로 실행 가능한 배포본이라는 뜻은 아니다.

```powershell
$env:OPENBLAS_NUM_THREADS='1'
$env:OMP_NUM_THREADS='1'
$env:MKL_NUM_THREADS='1'
python -m tools.league_tail_position_experiment --source runs/league_tail_curriculum_20261011 --out runs/league_tail_position_20261012
```

동일 경로가 이미 있으면 재실행하지 않는다. 이어받을 모델, 원시 결과, 입력 해시가 모두 준비된 환경에서만 실행하며 복원된 상태와 실제 프로세스를 먼저 확인한다.
